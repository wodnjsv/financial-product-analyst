# 금융상품 Agent 핵심 평가 질문 명세

**Date:** 2026-08-10

**Status:** Task 1 reinforced with official competition briefs on 2026-08-15

**Scope:** 서버를 제외한 금융 Agent 핵심 동작의 질문 이해, 문맥 해소, 검색 계획, 검증, 답변 또는 제한 판단

## 1. 목적

이 문서는 금융상품 Agent가 실제 평가 질문을 어떻게 해석하고 처리해야 하는지 먼저 고정한다. 온톨로지, 데이터 모델, 검색기, Agent 프롬프트는 이 질문 세트에서 요구하는 개념과 관계만 우선 구현한다. 질문에 필요하지만 주최 측 마스터에 없는 데이터는 공식성이 검증된 외부 출처에서 보강한다.

요구사항의 공식 기준에는 네 개의 상품 마스터와 API 규격뿐 아니라 주최측의 과제설명·기술세션 자료도 포함한다. 두 PDF에서 추출한 요구사항과 페이지별 근거는 [공식 과제·기술 요구사항](../../reference/official-competition-requirements.md)에 정리한다. 원본 PDF는 저장소에 넣지 않는다.

추적 가능한 `tests/gold/core_questions.json`에는 원본 금융상품 행이나 정답 상품번호를 저장하지 않는다. 저장소에는 질문을 어떤 단계와 필드로 해석해야 하는지, 어떤 규칙으로 답하거나 제한해야 하는지만 기록한다. 주최 측 원본 및 승인된 공식 외부 데이터에서 산출한 정답 행과 결과 해시는 로컬의 무시된 평가 산출물로 관리한다.

모든 평가 데이터의 공통 컷오프는 **2026-07-11**이다. 이는 모든 값의 실제 측정일을 7월 11일로 바꾼다는 의미가 아니다. 관측·적용일이 컷오프 이하여야 하고, 가능한 경우 해당 정보가 실제로 공개·이용 가능해진 시각과 빈티지도 컷오프 이하여야 한다. 7월 11일 현재 알 수 있었던 최신 공식 값을 사용하고 각 값의 실제 기준일을 별도로 보존한다. 컷오프 이후 발표된 과거기간 값이나 사후 수정치는 사용하지 않는다.

외부 API는 질문에서 요구하는 공백을 채울 때만 사용한다. 현재 질문 세트에는 KRX가 국내 ETF 동일일 가격·NAV와 일부 식별·지수 관계에, ECOS가 교차통화 AUM의 공식 환율에 조건부로 연결될 수 있다. FRED 시계열을 직접 요구하는 현재 질문은 없으므로 연결을 전제로 하지 않는다.

## 2. 이번 검토에서 추가된 핵심 요구사항

### 2.1 여러 조건과 관계가 결합된 질문

평가 질문은 단일 필드 조회가 아니라 다음과 같은 의존 단계를 포함할 수 있다.

```text
운용사 식별
→ 그 운용사의 상품만 필터링
→ 동일한 1년 수익률 정의로 순위 계산
→ 1위 상품을 중간 결과로 바인딩
→ 해당 상품과 유사한 상품 탐색
→ 순위와 유사성 근거를 각각 검증
```

LLM이 이 전체 과정을 한 번에 자유롭게 답하지 않는다. 질문을 `subtasks`와 `dependencies`로 분해하고, 결정론적 도구가 앞 단계 결과를 만든 뒤 다음 단계가 그 결과를 사용한다.

### 2.2 여러 문장에 걸친 지시어와 생략

다음 문장의 `이 상품`, `그 운용사`, `위 상품들`은 별도 청크의 독립 질의로 처리하면 안 된다.

```text
가람자산운용 ETF 중 1년 수익률이 가장 높은 상품을 알려줘.
이 상품의 위험등급을 보여주고 비슷한 ETF도 찾아줘.
```

두 번째 문장의 `이 상품`은 원문에 이름이 없어도 `첫 번째 문장의 실행 결과 중 top_product`에 바인딩돼야 한다. 따라서 먼저 전체 요청을 문장 단위로 분해하고, 아래 구조화 상태를 유지한다.

```text
RequestContext
├─ segments
├─ named_entities
├─ intermediate_result_bindings
├─ reference_mentions
└─ dependency_edges
```

청크는 검색 단위일 수 있지만 문맥의 소유 단위가 아니다. 검색 청크마다 원 요청 ID, 문장 ID, 선행 문장, 부모 상품 또는 문서 ID를 함께 전달한다.

### 2.3 지시어 해소 우선순위

지시어는 다음 순서로 해소한다.

1. 같은 문장에 명시된 고유 상품번호, ISIN, 티커 또는 정확한 상품명
2. 같은 문장에 있는 유일한 타입 호환 엔티티
3. 앞 문장에서 명시된 가장 최근의 유일한 타입 호환 엔티티
4. 앞 단계가 생성하기로 한 유일한 중간 결과 바인딩(예: `s1.top_product`)
5. 후보가 둘 이상이거나 타입이 충돌하면 하나를 임의 선택하지 않고 모든 호환 후보를 함께 반환하거나, 후보별 답변이 금융적으로 무의미하면 제한 또는 거절

단순히 벡터 유사도가 높다는 이유로 지시 대상을 결정하지 않는다. 지시어 해소 결과에는 대상 ID, 근거 문장, 바인딩 종류, 신뢰 상태를 남긴다.

이번 평가 세트는 동일 요청 안의 여러 문장 문맥을 필수 범위로 둔다. [공식 평가 API 규격](../../reference/official-evaluation-api.md)은 요청마다 `question_id`와 `question`만 전달하고 세션 ID나 이전 대화 이력을 전달하지 않는다. 따라서 평가 범위는 현재 `question` 문자열 안의 문맥으로 한정하며, 이전 평가 요청의 문맥에 의존하지 않는다.

### 2.4 단일 질문·단일 답변 정책

대회 모드에서는 사용자에게 되묻는 절차가 없다. 모호성은 다음 순서로 처리한다.

1. 질문에 명시된 기준을 그대로 적용한다.
2. 명시되지 않은 기준은 승인된 상품군별 기본 규칙을 적용하고 적용 사실을 답변에 밝힌다.
3. 여러 후보가 남으면 하나를 추측하지 않고 후보별 결과를 함께 제시한다.
4. 서로 다른 의미의 지표는 승인된 방법으로만 환산하고, 환산할 수 없으면 상품군 또는 지표 유형별로 분리한다.
5. 근거 있는 답변이 불가능하면 필요한 데이터와 한계를 설명하거나 거절한다.

따라서 `clarification`은 대회용 최종 응답 유형이 아니다. 평가 응답은 `answer`, `limitation`, `abstention` 중 하나이며, 내부 실행 오류는 별도의 통제된 오류 경로로 처리한다.

### 2.5 공식 평가 구성과 답변 불가 판정

과제설명 자료는 총 30문항, 난이도 상·중·하 각 10문항을 예정하고 있으며 세부 수는 변경될 수 있다고 명시한다. 이 중 약 5문항은 제공·승인 데이터로 확인할 수 없는 의도적인 답변 불가 질문이다. 내부 골드 세트는 공식 문항 수와 별개로 더 넓은 실패 유형을 검증한다.

답변 불가 판정은 다음 세 종류를 포함한다.

1. **온톨로지 제약 위반:** 허용된 신용등급 체계에 없는 `AAAA` 같은 값
2. **근거 관계 부재:** 승인 데이터에서 `Kimi`와 금융상품의 관계를 입증할 수 없는 경우
3. **기준일 엔티티 부재:** 2026-07-11 상품 마스터에서 정확한 `KODEX AI로봇 ETF`를 식별할 수 없는 경우

이름이 비슷한 상품이나 LLM의 사전지식으로 빈 근거를 채우지 않는다. 답변 불가 질문도 평가 API에서는 `200 OK`와 동일 스키마를 사용하고, `answer`에 확인할 수 없는 이유를 명시한다.

### 2.6 저장소별 검색 역할과 Federated Retrieval

각 평가 케이스는 질문을 의미 단위로 분해한 뒤 하위 작업별 검색 위치를 기록한다.

| 검색 역할 | 담당 작업 |
| --- | --- |
| `rdb` | 정확한 필터, 정렬, 순위, 집계, 금융 계산 |
| `graph` | 구성종목, 기업 지배관계, 운용관계, 지수·테마처럼 명시적인 관계 경로 |
| `vector` | 전략, 구조, 위험, 동향 같은 서술형 공식 문서 후보 검색 |
| `keyword` | 정확한 상품명, 기업명, 티커, ISIN, 문서 문구 검색 |

구조화 조건을 Vector 유사도로 판정하지 않고, Graph 관계를 이름의 의미 유사성으로 대신하지 않는다. 복합 질문은 `분해 → 온톨로지 grounding → 하위 작업 routing → 결과 mapping → 근거 검증` 순서로 실행한다.

## 3. 사용자 예시의 데이터 지원성 판단

### 3.1 “삼성전자 들어간 ETF AUM순으로 5개 알려줘”

필요한 관계와 값은 다음과 같다.

```text
SamsungElectronics
← heldSecurity ← ETF
→ hasAUM → AUM value and applicable date
```

현재 네 개의 마스터 레퍼런스에는 ETF 구성종목 또는 편입비중 필드가 없다. 국내 ETF에는 `du_last_aum`이 있지만, `ETF → holdsSecurity → 삼성전자` 관계를 증명할 수 없다. 설명회 요구에 따라 ETF 구성종목은 반드시 추가해야 하는 핵심 데이터로 분류한다.

따라서 현재 기대 동작은 다음과 같다.

- 상품명이나 전략 설명에 `삼성전자`가 들어 있다는 이유로 편입을 추정하지 않는다.
- 편입종목 데이터가 없음을 설명하고 결과를 만들지 않는다.
- 승인된 공식 구성종목 소스를 추가해 `ETF 상품 ID`, `편입종목 ID`, `편입비중 또는 보유수량`, `기준일`, `출처`를 연결한다.
- 편입관계가 검증된 ETF만 국내 ETF `du_last_aum`의 동일 단위와 기준일 조건으로 내림차순 정렬한다.

이 질문은 현재 상태에서는 `requires_additional_data`지만 최종 목표에서는 `supported`이며, 온톨로지의 핵심 역량 질문으로 유지한다.

### 3.2 “어떤 운용사의 상품 중 연간수익률이 가장 높은 상품과 비슷한 상품”

국내 ETF로 범위가 확정되면 다음 필드로 처리할 수 있다.

```text
운용사             → cu_fund_mgmt_co
ETF 여부           → pd_grp_no = 'ETF'
1년 누적수익률     → du_er_1y
수익률 기준일      → du_upt_dt
유사성 설명 후보   → wu_inv_ast_type, wu_inv_rgn,
                     cu_strtegy, cu_lev_fector, cu_base_index
```

주의사항:

- 별도 기간이나 정의가 없는 `연간수익률`은 최근 1년 역사적 누적수익률로 해석한다.
- 공식 가격·NAV 입력으로 같은 1년 누적수익률을 재현할 수 있으면 결정론적으로 계산한다.
- 여러 해의 완전한 누적수익률만 있다면 `(1 + R_total)^(1/n) - 1`로 CAGR을 계산하고 `연환산수익률`임을 표시한다.
- 채권 YTM과 같은 기대 연율은 과거 1년 실현수익률과 경제적 의미가 다르므로 지표 유형을 표시하고 분리 또는 제한과 함께 비교한다.
- 해외 ETF 마스터에는 검증 가능한 1년 수익률 필드가 없다.
- 공모펀드에는 `fd_yr1_ern_r`가 있지만 현재 운용사 명칭이 없고 기관 코드만 있으므로 운용사명 검색에는 기관 마스터가 추가로 필요하다.
- 상품군을 생략한 운용사 질문은 지원 가능한 모든 상품군을 검사하며, 동일 의미로 정규화할 수 없는 결과는 상품군 또는 지표 유형별로 분리하고 한계를 명시한다.

### 3.3 공식 복합 질문이 추가로 요구하는 경로

공식 예상 질문은 기존 구성종목 사례보다 더 긴 관계와 비정형 근거를 요구한다.

```text
캠브리콘
→ 공식 기업·증권 식별자
→ ETF 구성종목
→ 중국 투자지역 + 반도체 산업분류

에코프로
→ 공식 자회사 관계
→ 상장 증권
→ ETF 구성종목
→ ETF AUM 순위
→ 공식 상품 문서의 위험요인

우주항공 테마
→ 공식 테마 관계 이벤트
→ 관계 유효일·게시일이 최근 6개월 범위
→ 관련 ETF
```

`국민성장펀드의 구조·투자전략·동향`은 상품 마스터의 한 행으로 답하지 않는다. 정확한 대상 식별 뒤 공식 정책·상품 문서를 Keyword와 Vector로 찾고, 문서의 발행기관·게시일·적용일·페이지·절을 보존하여 구조·전략·동향 주장을 각각 다른 근거에 연결한다.

## 4. 공식 외부 데이터와 기준일 정책

### 4.1 출처 우선순위

1. 주최 측 제공 데이터
2. 감독기관·거래소·공시 시스템의 공식 데이터
3. 상품 발행사·자산운용사·지수 제공기관의 공식 공시 또는 파일
4. 공식 원문 위치를 찾기 위한 보조 검색 출처

4번 출처만으로 금융 사실을 확정하거나 최종 답변의 증거로 사용하지 않는다. 동일 필드가 주최 측 데이터와 충돌하면 주최 측 데이터를 평가 기준으로 유지하고 충돌을 기록한다. 외부 데이터는 주로 주최 측에 없는 관계와 필드를 보완한다.

### 4.2 모든 외부 레코드에 필요한 계보

- 공식 게시기관
- 원문 URL 또는 문서 식별자
- 데이터셋 또는 문서명
- 실제 적용 기준일
- 게시일 또는 공시일
- 최초 이용 가능일과 과거 빈티지 식별자(원천이 제공하는 경우)
- 수집일시
- 원문 파일 또는 응답의 체크섬
- 파서와 매핑 규칙 버전
- 상품·증권 식별자 연결 방식
- 사용 조건 또는 라이선스 메모

### 4.3 컷오프 규칙

- `applicable_date <= 2026-07-11`인 값만 평가 스냅샷에 들어갈 수 있다.
- 가능한 경우 `published_at`, `available_at`, `vintage_date`도 모두 `2026-07-11` 이하여야 한다.
- 7월 11일이 휴장일이거나 공식 파일이 발행되지 않은 경우에는 그 이전의 최신 공식 기준일을 사용한다.
- 실제 기준일이 7월 10일이면 답변에도 7월 10일이라고 표시하며 7월 11일 값이라고 바꾸지 않는다.
- 7월 11일 이후 정정·개정 데이터는 별도 연구용 버전으로 분리하고 평가 스냅샷을 소급 변경하지 않는다.
- 기간 표시는 컷오프 이전이지만 실제 발표일이 이후인 월·분기·연간 통계는 사용하지 않는다.
- 컷오프 시점 빈티지를 재현할 수 없고 현재 수정치만 확보되는 값은 엄격한 과거시점 답변에서 제외한다.
- 교차통화 비교의 기본 표시통화는 KRW다.
- 환율은 2026-07-11 당일의 승인된 공식 고시값을 사용하고, 당일 공식 관측값이 없으면 그 이전 최신 공식값만 사용한다.
- 환산 결과에는 기준·상대 통화, 환율 종류, 실제 환율 관측일, 공식 출처, 적용 공식을 함께 남긴다.

### 4.4 우선 확보할 추가 데이터

1. 국내·해외 ETF 구성종목과 편입비중
2. 구성종목 식별자, 발행사, 산업·섹터·국가 분류
3. 기업의 지배·종속·자회사 관계와 상장 여부처럼 다단계 질문에 필요한 공식 관계
4. 상품 구조·전략·위험요인·동향을 뒷받침하는 공식 문서와 문서 청크 계보
5. 테마·산업·기업·상품 연결의 발생일·유효기간·공개일을 가진 공식 관계 이력

7. 동일 기준일 비교가 가능한 가격·NAV·수익률 입력 시계열
8. 교차통화 비교를 위한 공식 환율
9. 운용사·발행사 코드와 공식 명칭을 연결하는 기관 마스터
10. 공모펀드 대표펀드·클래스·보수·판매 조건
11. 채권 발행사, 신용등급, 등급 기준일, 공식 발행조건
12. 판매·거래정지·연금 가능 여부 등 운영 상태를 보완하는 공식 상태 데이터

각 데이터는 질문 유형과 직접 연결될 때만 수집한다. 확보 가능한 데이터를 모두 모으는 방식으로 범위를 넓히지 않는다.

## 5. “비슷한 상품”의 확정 기본 규칙

사용자가 유사성 기준을 지정하지 않았을 때는 모든 금융상품에 하나의 공식을 적용하지 않는다. `기준 상품 식별 → 상품군별 정책 선택 → 하드 필터 → 결정론적 가중 점수 → Top-K → 근거 설명` 순서로 처리한다.

### 5.1 공통 하드 필터

- 기준 상품과 같은 상품군만 비교한다. ETF와 ETN, ETF와 공모펀드, 채권과 펀드를 기본 유사상품에 섞지 않는다.
- ETF는 일반형·레버리지형·인버스형과 배수·방향이 같아야 한다.
- 상품의 손익구조를 본질적으로 바꾸는 특수 구조가 공식 데이터로 확인되면 상품군 정책의 하드 필터를 적용한다.
- 기준 상품 자신, 유효하지 않은 상품 식별자, 질문의 판매·거래·기준일 조건을 통과하지 못한 상품은 제외한다.
- 하드 필터 값이 결측이면 일치한다고 가정하지 않는다. 필수 구조를 확인할 수 없는 후보는 제외 사유를 남긴다.

환헤지 여부나 합성·실물 복제처럼 상품 차이를 설명하지만 모든 질문에서 손익구조를 완전히 바꾼다고 단정하기 어려운 항목은 기본 점수축으로 둔다. 사용자가 해당 조건을 명시한 경우에만 하드 필터로 승격한다.

### 5.2 상품군별 초기 가중치

아래 가중치는 첫 오프라인 벤치마크용 `v1` 기준이다. 평가 질문과 전문가 검토 없이 모델이 요청마다 가중치를 바꾸지 않는다. 벤치마크에서 변경할 경우 정책 버전과 변경 이유를 기록한다.

| 상품군 | 점수축과 가중치 |
| --- | --- |
| 국내·해외 ETF | 기초자산·자산군 25%, 투자지역 15%, 전략·추종지수 20%, 구성종목 중첩 20%, 위험등급 10%, 환헤지·복제·분배 등 기타 구조 10% |
| 공모펀드 | 자산군·운용속성 30%, 투자지역 20%, 운용전략·벤치마크 25%, 위험등급 15%, 환헤지·설정유형 등 기타 구조 10% |
| 국내채권 | 발행주체·발행사 업종 20%, 신용등급 25%, 잔존만기 20%, 채권종류·금리구조 15%, 통화 10%, 같은 정의의 수익률 또는 YTM 10% |

ETF 구성종목 중첩은 정규화된 편입비중에 대해 다음 식을 기본값으로 사용한다.

```text
weighted_holdings_overlap(A, B)
= Σ security min(weight_A, weight_B)
```

현금, 파생상품, 통화 포지션을 보통주 종목과 같은 식별자로 합치지 않는다. 서로 다른 구성 기준일을 사용하면 실제 날짜 차이를 근거에 표시한다.

### 5.3 결측과 점수 신뢰도

- 각 축의 입력이 양쪽 상품에 모두 존재하고 공식 의미가 호환될 때만 그 축을 계산한다.
- 계산 가능한 축의 가중치 합으로 점수를 재정규화하고, 원래 전체 가중치 중 계산된 비율을 `score_coverage`로 별도 표시한다.
- `score_coverage < 60%`이면 숫자 유사도 순위를 만들지 않고 제한으로 응답한다.
- 같은 점수면 `score_coverage`가 높은 후보, 그다음 공식 상품 ID 오름차순으로 안정 정렬한다.
- 결측은 불일치나 0점으로 위장하지 않으며, 임베딩 점수로 채우지 않는다.

### 5.4 답변과 증거

- 기준 상품 자체를 제외하고 기본 Top-K 후보를 반환한다.
- 후보별 총점, 점수 커버리지, 통과한 하드 필터, 축별 점수, 같은 점과 다른 점을 보여준다.
- 점수 계산에 사용한 원천 필드, 공식 구성종목 기준일, 정책 ID와 버전을 증거에 연결한다.
- 유사도는 투자 추천이나 미래성과 예측이 아니라고 표현한다.
- 임베딩은 향후 설명 텍스트의 보조 후보 생성에만 사용할 수 있으며 하드 필터나 기본 결정론적 점수를 덮어쓰지 못한다.

## 7. 질문 유형과 케이스 수

## 8. 수용 기준

- 전체 요청을 먼저 분석하고 문장별 청크를 독립 질문처럼 처리하지 않는다.
- 모든 지시어는 유일한 엔티티 또는 중간 결과에 바인딩되거나, 복수 후보 반환·제한·거절의 단일 턴 경로로 끝난다.
- 대회 모드의 최종 답변은 사용자에게 추가 질문을 요구하지 않는다.
- 무조건적인 `연간수익률`은 최근 1년 역사적 누적수익률을 기본값으로 하고, 다른 연율 지표를 사용하면 의미와 계산 방법을 표시한다.
- 교차통화 값은 KRW로 환산하며 승인된 공식 환율의 실제 관측일이 2026-07-11 이후일 수 없다.
- 컷오프 이전 기간의 값이라도 2026-07-11 이후에 처음 발표되거나 수정된 값이면 엄격한 스냅샷에 사용하지 않는다.
- 외부 API는 승인 질문의 필수 데이터 요구사항에 연결될 때만 사용하고, 관계없는 거시·시장 데이터를 답변에 덧붙이지 않는다.
- 다단계 질문은 선행 결과가 생성되기 전에 후행 단계를 실행하지 않는다.
- 구조화 조건은 SQL 또는 일반 코드의 하드 필터다.
- 각 하위 작업은 RDB·Graph·Vector·Keyword 중 검증 가능한 검색 역할에 연결된다.
- 온톨로지는 프롬프트 설명이 아니라 엔티티 해소, 관계 경로 선택, 허용 값 검증과 검색 라우팅에 사용된다.
- 지식 그래프의 모든 관계 edge는 실제 인스턴스, 적용일과 원천을 가져야 한다.
- 상품 문서 청크는 상품 ID, 문서 ID, 페이지·절과 부모 문맥을 보존한다.
- 최근 기간을 묻는 관계는 `published_at`, `available_at`, `valid_from`, `valid_to`를 사용해 컷오프 당시의 기간 경계를 계산한다.
- 유사상품은 비교 축을 공개하며, 근거 없는 의미 유사성만으로 만들지 않는다.
- 상품군별 유사도 정책은 하드 필터와 가중치를 결정론적으로 적용하고 점수 커버리지가 60% 미만이면 숫자 순위를 만들지 않는다.
- 필드나 관계가 없으면 지원하는 척하지 않고 추가 데이터 필요 또는 제한으로 답한다.
- ETF 구성종목을 포함한 필수 외부 데이터는 승인된 공식 출처와 2026-07-11 컷오프를 통과해야 한다.
- 외부 데이터가 주최 측 데이터와 충돌하면 자동 덮어쓰지 않고 평가 기준과 충돌 사실을 남긴다.
- 계산과 순위에는 사용 필드, 기간, 단위, 기준일, 제외 사유가 남는다.
- 추천 표현은 사용자가 제시한 조건에 따른 후보 탐색으로 제한한다.
- 공식 답변 불가 사례는 유사명 상품이나 일반지식으로 대체하지 않고 동일한 200 응답 스키마 안에서 확인 불가를 명시한다.

## 9. 확정 상태와 후속 결정

1. 공식 평가 요청은 세션 상태를 전달하지 않으므로 이전 대화 턴 문맥은 평가 범위에 포함하지 않는다.
2. 하나의 `question` 안에 포함된 여러 문장과 중간 결과 바인딩은 필수 범위다.
3. 추가 공식 데이터의 실제 원천 활성화는 ADR-0007에서 질문별 필요성과 함께 결정한다.
4. 내부 골드 세트는 공식 예상 30문항보다 넓은 52개 유형으로 유지한다.
5. 공식 과제 자료는 Graph와 Vector 검색 능력을 요구하지만 별도 Graph DB·Vector DB 또는 멀티 에이전트 구조를 강제하지 않는다.
6. 52개 질문 유형의 구현 순서는 Task 2 결정 이후 확정한다.
