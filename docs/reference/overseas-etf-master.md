# 해외 ETF 마스터 데이터 분석 및 필드 레퍼런스

**테이블 ID:** `PREF02N001`

**기준 파일:** `PREF02N001_해외ETF마스터_20260711_datarows.xlsx`

**분석일:** 2026-08-04

**문서 성격:** 데이터 사전, 해석 참고자료, 금융상품 Agent 구현 가드레일

> 이 문서는 로컬에 보관된 주최 측 원본 워크북의 스키마, 실제 첫 10개 데이터 행, 전체 필드별 결측·분포를 분석해 작성한 파생 문서다. 원본 워크북과 행 단위 원본값은 저장소에 포함하지 않는다. 제공 스키마에는 한글 필드 설명이 없으므로, 필드명과 실제 값만으로 확정할 수 없는 의미는 `추정` 또는 `확인 필요`로 표시한다.

## 1. 한눈에 보는 결론

- 한 행은 미국 시장에서 거래되는 해외 상장지수상품 한 종목이다. 총 5,646행이다.
- 테이블 이름은 해외 ETF 마스터지만 실제로는 **ETF 5,587개와 ETN 59개**가 함께 들어 있다. ETF만 찾을 때는 `pd_grp_no = 'ETF'`를 적용해야 한다.
- `pd_itm_no`는 전 행에서 고유하고 결측이 없어 대표 식별자로 사용하기 가장 적합하다.
- `pd_isin_cd`와 `pd_lipper_id`는 결측과 중복이 있어 단독 기본키로 사용하면 안 된다.
- 상품통화 `pd_curr_cd`와 거래통화 `pd_trd_ccy`는 서로 다른 개념이다. 거래통화는 전부 USD지만 상품통화는 USD 외에 INR 1개와 결측 8개가 있다.
- ETF의 투자자산은 주식뿐 아니라 채권, 대체자산, 혼합자산, 원자재, 단기금융상품까지 포함한다. `wu_inv_ast_type`과 `wu_inv_rgn`이 가장 직접적인 분류 필드다.
- 기초지수 `cu_base_index`에는 실제 지수명뿐 아니라 “운용사가 제공하지 않음”, “Lipper DB에서 확인할 수 없음”이라는 문장형 결측값 2,705개가 들어 있다.
- 레버리지 배수 `cu_lev_fector`는 5,646개 전부 결측이다. 실제 표본에는 2배 레버리지 상품이 존재하므로 이 필드만으로 레버리지 상품을 찾을 수 없다.
- `du_base_dt_match_yn`이 존재하는 5,636행은 모두 `N`이다. NAV 기준일과 종가 기준일이 다르므로 이 파일의 값만 단순 결합해 괴리율을 계산하면 안 된다.
- `du_diff_rt`는 3개만 존재하고 그중 극단값도 있으며, `du_er_1d`는 존재하는 5,388개가 전부 0이다. 제공 괴리율과 1일 수익률은 분석에 사용할 수 없는 상태다.
- `du_last_nav`는 682개만 존재한다. 반면 NAV 기준일 `du_nav_base_dt`는 전 행에 있으므로, 기준일이 있다고 NAV 값도 있다고 간주하면 안 된다.
- `ru_mkt_volume`은 채워진 5,636행에서 `du_vol_1d`와 같다. `ru_mkt_price`도 다수는 종가와 같지만 406행은 다르며 기준시각 필드가 없다. 이 두 필드를 실시간 시세라고 단정하면 안 된다.
- 파일명에는 2026-07-11이 표시되어 있지만 구조·분류와 NAV 기준일은 2026-06-14, 종가는 대부분 2026-06-16이다. 파일 추출일과 각 지표 기준일을 분리해야 한다.

### 2.1 행의 단위와 키

한 행은 하나의 해외 상장 ETF 또는 ETN 종목이다.

```text
미국 시장 상장지수상품
├─ ETF 종목 A → pd_itm_no A
├─ ETF 종목 B → pd_itm_no B
└─ ETN 종목 C → pd_itm_no C
```

식별자 상태는 다음과 같다.

| 필드 | 고유값 | 결측 | 중복 행 | 키 사용 판단 |
| --- | ---: | ---: | ---: | --- |
| `pd_itm_no` | 5,646 | 0 | 0 | 대표키로 적합 |
| `pd_itm_no_ma` | 5,646 | 0 | 0 | 대체 식별자로 사용 가능 |
| `pd_isin_cd` | 5,587 | 9 | 50 | 단독키로 부적합 |
| `pd_lipper_id` | 5,588 | 8 | 50 | 단독키로 부적합 |

원본 적재에서는 `pd_itm_no`를 대표키로 유지하고, ISIN과 Lipper ID는 외부 데이터 연결용 보조 식별자로 사용하는 것이 안전하다.

첫 10개 데이터 행을 직접 확인했다. 행 단위 식별자와 상품명은 저장소에 복제하지 않고 관찰 결과만 요약한다.

| 관찰 항목 | 첫 10행에서 확인된 내용 | 의미 |
| --- | --- | --- |
| 상품군 | ETF 10개 | 이 표본에는 ETN이 없지만 전체에는 59개 존재 |
| 투자자산 | 주식 5, 채권 3, 혼합자산 1, 대체자산 1 | ETF가 주식형만을 뜻하지 않음 |
| 투자지역 | 미국 8, 글로벌 2 | 상장시장과 투자지역을 구분해야 함 |
| 상품통화·거래통화 | 모두 USD | 전체에는 상품통화 INR 1개와 결측 8개가 존재 |

| 지수추종 표시 | `Y` 5, 결측 5 | 기초지수명이 있어도 지수추종 표시가 없을 수 있음 |
| 지수복제방식 | `Optimized` 5, 결측 5 | 액티브·미분류 상품은 비어 있을 수 있음 |
| 레버리지 관련 | 배수·인버스 필드 모두 결측 | 전략 설명에는 약 2배 상품이 있어 전용 필드가 불완전함 |
| 전략 설명 | 10행 모두 영문 문장 존재 | 의미검색과 보조 분류에 유용하지만 구조화가 필요 |

| 기준일 일치 | 10행 모두 `N` | NAV와 종가를 바로 비교하면 안 됨 |
| 종가 기준일 | 9행은 2026-06-16, 1행은 2026-06-03 | 같은 파일에서도 종가 기준일이 다름 |
| NAV 기준일 | 10행 모두 2026-06-14 | 종가 기준일과 불일치 |
| 판매·거래상태 | 판매값 1, 거래정지값 0 | 두 상태는 별도 조건으로 다뤄야 함 |
| 액면가 | 모두 0 | 가격 또는 투자금액으로 사용할 수 없음 |

괴리율의 일반식은 다음과 같지만, 현재 파일에서는 그대로 계산하면 안 된다.

```text
괴리율(%) = (동일 시점 시장가격 ÷ 동일 시점 NAV - 1) × 100
```

이 파일은 종가와 NAV의 기준일이 전부 불일치하므로, 별도 시계열에서 동일 날짜의 값을 확보한 뒤 결정론적으로 계산해야 한다. 계산 결과에는 사용한 가격, NAV, 통화, 날짜, 출처를 함께 남긴다.

#### 규모와 유동성

| 필드 | 타입 | 쉬운 의미 | 실제 상태와 주의점 |
| --- | --- | --- | --- |
| `du_last_aum` | numeric | 최신 운용자산규모 | 5,459개 존재, 187개 결측, 8개는 0. ETF와 ETN에서 의미가 다를 수 있음 |
| `du_val_1d` | numeric | 1일 거래대금 | 5,636개 존재, 10개 결측, 187개는 0 |
| `du_vol_1d` | numeric | 1일 거래량 | 5,636개 존재, 10개 결측, 187개는 0 |

AUM과 유동성은 다른 개념이다.

- AUM이 크다: 상품에 들어 있는 자산 또는 지표가치 규모가 크다.
- 거래대금이 크다: 해당 거래일에 돈이 많이 오갔다.
- 거래량이 크다: 해당 거래일에 주식·증권 수량이 많이 거래됐다.

서로 가격이 다른 상품의 유동성을 비교할 때는 거래량만 보기보다 거래대금과 함께 보는 것이 안전하다.

## 5. ETF와 ETN을 먼저 분리해야 하는 이유

| 구분 | ETF | ETN |
| --- | --- | --- |
| 데이터 필터 | `pd_grp_no = 'ETF'` | `pd_grp_no = 'ETN'` |
| 보조 표시 | `cu_etn_yn` 결측 | `cu_etn_yn = 'Y'` |
| 건수 | 5,587 | 59 |
| 법적 구조 | 집합투자기구의 지분 | 금융기관이 발행한 채무증권 |
| 핵심 위험 | 기초자산 가격, 추적오차, 비용, 유동성 | 기초자산 가격, 발행사 신용, 만기·상환조건, 유동성 |
| `du_last_aum` | 펀드 규모로 해석 가능 | 발행잔액·지표가치 성격일 수 있어 확인 필요 |
| `du_last_nav` | 순자산가치 | 지표가치·상환가치에 가까울 수 있음 |

두 필드는 전체 데이터에서 정확히 일치한다.

```text
pd_grp_no = ETF → cu_etn_yn = NULL  5,587개
pd_grp_no = ETN → cu_etn_yn = Y        59개
```

ETN 59개는 대체자산 40, 원자재 11, 주식 8개로 분류되어 있다. ETF 검색에 이들을 섞으면 발행사 신용위험과 상환조건이 빠진 설명을 만들 수 있다.

## 6. 필드 간 핵심 관계

### 6.1 거래시장, 투자지역, 통화는 서로 다르다

```text
어디에 상장되었는가  → pd_mkt_id, pd_exg_mkt_cd
무엇에 투자하는가    → wu_inv_ast_type, wu_inv_rgn, cu_strtegy
무슨 통화로 표시되는가 → pd_curr_cd
무슨 통화로 거래되는가 → pd_trd_ccy
```

이 테이블은 `pd_mkt_id = 'US'`, `pd_trd_ccy = 'USD'`이지만 투자지역은 전 세계에 걸쳐 있다. 따라서 “미국 ETF”라는 표현이 다음 중 무엇을 뜻하는지 구분해야 한다.

- 미국 시장에 상장된 ETF
- 미국 주식·채권에 투자하는 ETF
- 미국 달러로 거래되는 ETF

### 6.2 종가와 NAV는 기준일을 먼저 맞춰야 한다

```text
시장 종가       du_clpr          ── 기준일: du_clpr_base_dt
NAV·지표가치    du_last_nav      ── 기준일: du_nav_base_dt
기준일 일치 여부                  ── du_base_dt_match_yn
```

현재 `du_base_dt_match_yn`은 값이 있는 전 행에서 `N`이다. 종가와 NAV를 같은 행에 있다는 이유만으로 나누어 괴리율을 만들면 서로 다른 날짜의 값을 비교하게 된다.

### 6.3 시장가격 필드가 두 개다

- `du_clpr`: 종가이며 `du_clpr_base_dt`와 `du_clpr_src`가 있다.
- `ru_mkt_price`: 시장가격이라는 이름이지만 기준일·기준시각이 없다.

5,230개는 같은 값이고 406개는 다르다. 과거 가격을 재현하거나 근거를 제시해야 하는 분석에서는 날짜와 출처가 있는 `du_clpr`를 우선 사용한다. `ru_mkt_price`는 별도 정의와 갱신시각을 확보하기 전까지 보조값으로만 둔다.

### 6.4 시장거래량 필드도 두 개다

`ru_mkt_volume`과 `du_vol_1d`는 채워진 5,636행에서 모두 같다. 현재 스냅샷에서는 서로 다른 지표라기보다 같은 일간 거래량을 두 위치에 적재한 것으로 보인다. 두 값을 합산하면 거래량을 이중 계산하게 된다.

### 6.5 지수추종, 복제방식, 기초지수는 함께 본다

| 확인 질문 | 필드 |
| --- | --- |
| 지수를 추종하는가 | `cu_index_tracking_yn` |
| 어떤 지수인가 | `cu_base_index` |
| 어떤 방식으로 복제하는가 | `cu_index_repl_mthd` |
| 실제 투자목적은 무엇인가 | `cu_strtegy` |

기초지수 문자열이 있다고 반드시 패시브 인덱스 ETF는 아니다. 액티브 ETF의 비교지수가 들어 있을 수 있으므로 `cu_index_tracking_yn`과 전략 설명을 함께 확인한다.

### 6.6 레버리지·인버스는 전용 필드만으로 판별할 수 없다

`cu_lev_fector`가 전부 결측이고 `cu_inverse_short_yn`도 171개만 채워져 있다. 안전한 분류 순서는 다음과 같다.

1. 구조화된 `cu_inverse_short_yn`을 우선 적용한다.
2. 상품명 `pd_nm`과 전략 설명 `cu_strtegy`에서 `2x`, `3x`, `inverse`, `short`, `daily` 같은 표현을 탐지한다.
3. 탐지 결과를 `derived_leverage_flag`, `derived_leverage_factor` 같은 파생 필드로 별도 저장한다.
4. 원본 필드와 파생 근거 문구를 함께 보존하고, 확정값이 아닌 추정 분류로 표시한다.

장기수익률이 기초자산 누적수익률의 정확한 배수가 된다고 설명해서도 안 된다. 레버리지·인버스 상품은 보통 일간 목표를 재설정하므로 경로와 변동성의 영향을 받는다.

## 7. 결측과 이상값 처리 규칙

### 7.1 `NULL`, 0, 문장형 결측을 구분한다

| 상태 | 예 | 처리 원칙 |
| --- | --- | --- |
| 물리적 결측 | `NULL`, 빈 셀 | 알 수 없음 또는 적용 불가로 유지 |
| 문장형 결측 | 기초지수 미제공·DB 미존재 문장 | 분석값은 `NULL`, 사유코드는 별도 보존 |
| 0이지만 사실상 미산출 | `du_er_1d`, `pd_lst_price` | 유효한 0으로 사용하지 않음 |
| 실제 0일 수 있음 | `du_vol_1d`, `du_val_1d` | 휴장·신규상장·거래정지 여부와 함께 확인 |
| 극단값 | `du_diff_rt`의 매우 큰 값 | 단위·산식·기준일 검증 전 제외 |

### 7.2 사용 불가 또는 매우 제한적인 필드

| 필드 | 이유 | 권장 조치 |

| `du_er_1d` | 존재값 전부 0 | 별도 가격 시계열로 재계산 |
| `du_diff_rt` | 3개만 존재, 극단값 포함 | 동일 기준일 가격과 NAV로 재계산 |
| `pd_lst_price` | 거의 전부 0 | 가격·액면가 분석에 사용하지 않음 |
| `wu_core_yn` | 103개 `N`, 나머지 결측, `Y` 없음 | 핵심·추천 여부 판단에 사용하지 않음 |
| `ru_mkt_price` | 기준시각 없음, 종가와 406개 불일치 | 실시간 현재가로 사용하지 않음 |

### 7.3 날짜 정규화

날짜 형식이 섞여 있다.

- `YYYYMMDD`: `cu_upt_dt`, `du_clpr_base_dt`, `du_upt_dt`, `pd_lstg_dt`, `wu_upt_dt`
- 타임스탬프: `du_nav_base_dt`

적재 시 모두 날짜형으로 변환하되 원본 문자열을 별도 보존한다. `pd_lstg_dt`의 0 값 8개는 정상 날짜가 아니므로 `NULL`과 `INVALID_ZERO` 사유로 분리한다.

### 7.4 결측을 부정값으로 바꾸지 않는다

다음 변환은 금지한다.

```text
cu_index_tracking_yn NULL → N
cu_inverse_short_yn NULL  → N
cu_etn_yn NULL            → N
wu_core_yn NULL           → N
```

현재 `cu_etn_yn`은 `pd_grp_no`로 보완할 수 있지만, 나머지 필드는 결측이 실제 `N`인지 미수집인지 구분할 근거가 없다.

## 8. 금융상품 Agent가 안전하게 사용하는 규칙

### 8.1 필터링은 결정론적으로 한다

사용자 질문을 구조화한 뒤 데이터베이스에서 정확히 필터링한다.

```text
“미국에 투자하는 주식형 해외 ETF”
→ pd_grp_no = 'ETF'
→ wu_inv_ast_type = 'Equity'
→ wu_inv_rgn = 'United States of America'
```

LLM은 질문 해석과 설명을 담당하고, 상품군 분리·필터·정렬·금융계산은 코드나 SQL이 담당해야 한다.

### 8.2 추천 전 최소 검사

1. `pd_grp_no`로 ETF와 ETN을 분리한다.
2. `pd_itm_no`가 있는지 확인한다.
3. `pd_sale_yn`, `pd_tr_yn`, `pd_lstg_dt`를 확인한다.
4. 최신 종가 기준일 `du_clpr_base_dt`와 거래량을 확인한다.
5. 상품통화와 거래통화를 구분한다.
6. 레버리지·인버스 추정 여부를 확인한다.
7. ETN이면 발행사 신용위험과 상환구조가 이 테이블에 충분하지 않음을 알린다.

### 8.3 가격과 성과 질문의 제한

- “현재가”에는 `ru_mkt_price`를 그대로 쓰지 않는다. 갱신시각이 있는 외부 시세가 필요하다.
- “오늘 수익률”에는 전부 0인 `du_er_1d`를 쓰지 않는다.
- “괴리율”에는 `du_diff_rt`를 쓰지 않는다. 동일 기준일 가격·NAV가 필요하다.
- “유동성”은 거래량과 거래대금을 함께 본다.
- “저렴한 ETF”라는 비용 질문에는 `cu_charge_rt`의 단위와 포함 범위를 먼저 확인한다.
- 통화 노출은 `pd_trd_ccy`만으로 판단하지 않는다. 투자자산 통화와 환헤지 정보가 별도로 필요하다.

### 8.4 근거와 불확실성을 함께 답한다

Agent의 답에는 다음을 함께 남기는 것이 좋다.

- 적용한 상품군·자산군·지역 필터
- 사용한 가격과 기준일
- 사용한 통화
- 원본 필드인지 파생 분류인지
- 결측 또는 데이터 품질 제한
- ETF와 ETN 구조상 차이

## 9. 권장 정규화 모델

원본 컬럼은 보존하고 조회용 파생 컬럼을 별도로 만든다.

```text
원본 해외 ETF 마스터
├─ identity
│  ├─ product_id              ← pd_itm_no
│  ├─ product_type            ← pd_grp_no
│  ├─ isin                    ← pd_isin_cd
│  └─ lipper_id               ← pd_lipper_id
├─ listing
│  ├─ exchange_code           ← pd_exg_mkt_cd
│  ├─ listing_date            ← pd_lstg_dt
│  ├─ product_currency        ← pd_curr_cd
│  └─ trading_currency        ← pd_trd_ccy
├─ classification
│  ├─ asset_type              ← wu_inv_ast_type
│  ├─ investment_region       ← wu_inv_rgn
│  ├─ valid_base_index        ← 정제된 cu_base_index
│  └─ base_index_missing_reason
├─ strategy
│  ├─ objective_text          ← cu_strtegy
│  ├─ index_tracking_flag     ← cu_index_tracking_yn
│  ├─ replication_method      ← cu_index_repl_mthd
│  └─ derived_leverage_*      ← 이름·전략에서 추출한 추정값
├─ daily_market
│  ├─ open, high, low, close  ← du_opr, du_hpr, du_lpr, du_clpr
│  ├─ close_date              ← du_clpr_base_dt
│  ├─ traded_value            ← du_val_1d
│  └─ traded_volume           ← du_vol_1d
└─ valuation
   ├─ nav                     ← du_last_nav
   ├─ nav_date                ← du_nav_base_dt
   └─ date_match_flag         ← du_base_dt_match_yn
```

파생 분류에는 반드시 다음 메타데이터를 둔다.

- `derived_from_fields`: 어떤 원본 필드를 사용했는지
- `derived_rule_version`: 규칙 버전
- `derived_confidence`: 확정·높음·중간·낮음
- `derived_evidence`: 판정에 사용한 짧은 근거

## 10. 공식 정의가 추가로 필요한 항목

다음은 실제 값만으로 의미를 완전히 확정할 수 없다.

1. `cu_charge_rt`의 정확한 단위와 포함 비용 범위
2. `du_bpr`의 공식 산출 정의
3. `du_diff_rt`의 단위와 산식
4. `du_last_aum`의 통화 단위와 ETN에서의 의미
5. `pd_itm_no_ma`의 `ma` 의미와 생성 규칙
6. `pd_exg_mkt_cd` 숫자코드 `101`, `102`의 시장명
7. `pd_sale_yn`과 `pd_tr_yn`의 공식 코드표
8. `ru_mkt_price`의 기준시각과 `du_clpr`와 다른 406행의 원인
9. `wu_core_yn`의 선정 기준과 결측 의미
10. `cu_inverse_short_yn`의 적용 범위와 레버리지 상품 누락 기준

공식 코드북이나 원천 시스템 정의가 확보되면 이 문서의 `추정` 항목을 확정 정의로 갱신해야 한다.

## 11. 구현 체크리스트

### 적재

- [ ] 원본 워크북은 변경하지 않고 비추적 상태로 유지한다.
- [ ] `pd_itm_no`를 대표키로 유일성 검사한다.
- [ ] 날짜 문자열을 날짜형으로 변환하고 원문도 보존한다.
- [ ] 문장형 기초지수 결측을 정규화한다.
- [ ] 숫자 0과 미산출 기본값을 구분한다.

### 검색과 분류

- [ ] ETF 검색에는 `pd_grp_no = 'ETF'`를 기본 적용한다.
- [ ] ETN을 포함하면 신용위험을 별도로 설명한다.
- [ ] 자산군은 `wu_inv_ast_type`, 지역은 `wu_inv_rgn`을 우선 사용한다.
- [ ] 거래시장·투자지역·상품통화·거래통화를 별도 축으로 유지한다.
- [ ] 레버리지·인버스 파생 분류의 근거와 신뢰도를 보존한다.

### 가격과 계산

- [ ] 종가에는 `du_clpr_base_dt`를 함께 표시한다.
- [ ] NAV가 실제로 존재하는지 확인한다.
- [ ] 종가와 NAV 기준일이 같을 때만 괴리율을 계산한다.
- [ ] `du_er_1d`와 `du_diff_rt` 제공값을 그대로 쓰지 않는다.
- [ ] `ru_*`를 실시간 값으로 표시하지 않는다.
- [ ] 거래량 필드를 중복 합산하지 않는다.

## 12. 분석 범위와 재현 기준

- 스키마 워크북의 49개 필드명과 타입을 확인했다.
- 데이터 워크북의 헤더와 첫 10개 데이터 행을 직접 확인했다.
- 전체 5,646행에 대해 필드별 결측, 0, 주요 분류 분포, 식별자 고유성을 집계했다.
- ETF·ETN 표시, 통화 조합, 종가·NAV 기준일, `ru_*`와 `du_*` 관계를 교차 검증했다.
- 원본의 행 단위 식별자, ISIN, 상품명, 전략 원문은 이 문서에 복제하지 않았다.
- 이 문서는 특정 상품의 추천서가 아니라 데이터 이해와 구현을 위한 레퍼런스다.
