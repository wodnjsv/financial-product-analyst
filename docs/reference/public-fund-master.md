# 공모펀드 마스터 데이터 분석 및 필드 레퍼런스

**테이블 ID:** `PRFD01N001`

**기준 파일:** `PRFD01N001_공모펀드마스터_20260711_datarows.xlsx`

**분석일:** 2026-08-04

**문서 성격:** 데이터 사전, 분류체계 설명, 금융상품 Agent 구현 가드레일

> 이 문서는 로컬에 보관된 주최 측 원본 워크북의 스키마, 실제 첫 10개 데이터 행, 전체 필드별 결측·분포를 분석해 작성한 파생 문서다. 원본 워크북과 행 단위 원본값은 저장소에 포함하지 않는다. 필드명과 실제 값만으로 확정할 수 없는 의미는 `추정` 또는 `확인 필요`로 표시한다.

## 1. 한눈에 보는 결론

- 데이터는 95,619행, 45개 필드로 구성된다.
- **한 행은 서로 다른 펀드 하나가 아니다.** 같은 펀드 종목 `itm_no`가 서로 다른 펀드속성코드 `prfd_attr_cd`만 바뀐 채 반복된다.
- 스키마상 기본키는 `itm_no + prfd_attr_cd + zrin_fd_ivst_risk_gcd`이며 이 조합은 전 행에서 고유하다.
- 실제 고유 `itm_no`는 11,139개다. 한 종목은 중앙값 기준 8행, 최대 16행으로 반복된다. 11,139개 중 11,138개가 둘 이상의 속성코드를 가진다.
- 유효한 대표펀드번호 `rptt_ksd_itm_no`로 묶으면 2,626개 펀드군이 93,052행을 덮는다. 한 대표펀드군에는 중앙값 3개, 최대 15개의 `itm_no`가 있다.
- 따라서 분석 단위를 세 가지로 구분해야 한다: 원본 속성행, 펀드 종목·클래스 `itm_no`, 대표펀드군 `rptt_ksd_itm_no`.
- 같은 `itm_no`의 순자산과 9개 기간수익률은 반복 행마다 같다. 성과 순위와 규모 집계 전에 반드시 `itm_no`로 중복 제거해야 한다.
- 펀드 순자산 `fd_nast_suma`는 83,081행에 있지만 12,538행은 결측이고 2,478행은 0이다. 대표펀드군 안에서도 클래스별 값이 다를 수 있으므로 단순 합산하면 안 된다.
- 테이블 이름은 공모펀드 마스터지만 실제로는 공모 95,451행, 과거 일반사모 102행, 분류 결측 66행이 들어 있다. 공모만 찾을 때는 `prvo_pbff_desc = '공모'`를 적용해야 한다.
- 수익률은 기간별로 약 26,000~45,000행이 결측이다. 18개월·2년·3년·5년 수익률에는 -100% 미만 값도 있어 품질 검사가 필요하다.
- 수익률 기준일 필드가 없다. 파일명 날짜 2026-07-11을 성과 기준일로 확정해서는 안 된다.
- 위험등급코드에는 물리적 `NULL`이 아니라 문자열 `"NULL"` 18,416개가 있다. 이를 실제 결측으로 정규화해야 한다.
- 환헤지 여부는 29,761개가 결측이다. 해외투자 여부와 환헤지 여부를 같은 것으로 보면 안 된다.
- `ofsfd_yn`은 채워진 값이 모두 0이지만 해외투자펀드는 51,628행이다. 해외자산에 투자하는 국내 설정 펀드와 역외 설정 펀드는 다른 개념이다.
- 전체에서 한 행은 여러 필드가 옆으로 밀린 것으로 보이는 명백한 이상행이 확인된다. 코드 검증 없이 모든 값을 신뢰하면 안 된다.

## 2. 데이터셋의 진짜 행 단위

### 2.1 세 가지 분석 단위

```text
대표펀드군 rptt_ksd_itm_no
├─ 펀드 종목·클래스 itm_no A
│  ├─ 속성코드 prfd_attr_cd 1 → 원본 행
│  ├─ 속성코드 prfd_attr_cd 2 → 원본 행
│  └─ 속성코드 prfd_attr_cd 3 → 원본 행
└─ 펀드 종목·클래스 itm_no B
   ├─ 속성코드 prfd_attr_cd 1 → 원본 행
   └─ 속성코드 prfd_attr_cd 2 → 원본 행
```

| 분석 단위 | 대표 필드 | 실제 개수 | 언제 사용하는가 |
| --- | --- | ---: | --- |
| 원본 속성행 | 복합키 전체 | 95,619 | 원본 적재, 속성코드 분석 |
| 펀드 종목·클래스 | `itm_no` | 11,139 | 성과·위험·판매상태 비교 |
| 대표펀드군 | 유효한 `rptt_ksd_itm_no` | 2,626 | 같은 모펀드·펀드군 묶기, 중복 노출 축소 |

`itm_no`가 이름에 클래스 표시를 포함하는 사례가 많으므로, 실무적으로는 펀드 종목 또는 판매클래스에 가까운 단위로 해석할 수 있다. 다만 정확한 종목·클래스 생성 규칙은 공식 코드북 확인이 필요하다.

### 2.2 스키마 기본키

제공 스키마는 다음 세 필드를 PK로 지정한다.

- `itm_no`: 종목번호
- `prfd_attr_cd`: 펀드별속성코드
- `zrin_fd_ivst_risk_gcd`: 제로인 투자위험등급코드

세 필드 조합은 95,619행에서 중복이 없다. 현재 스냅샷에서는 같은 `itm_no` 안에서 위험등급코드는 변하지 않고 `prfd_attr_cd`만 변한다. 그래도 원본 적재 키는 제공 스키마를 그대로 유지하는 것이 안전하다.

## 3. 스키마 워크북의 분류 예시와 원본 필드의 차이

스키마 워크북의 `Sheet2_Sample`에는 원본 45개 필드와 별도로 6개의 `axis_*` 분류 예시가 있다.

| 분류 축 | 예시 값 | 쉬운 의미 |
| --- | --- | --- |
| `axis_fundType` | `SecuritiesFund`, `MoneyMarketFund` | 증권펀드·MMF 같은 펀드 유형 |
| `axis_redemptionType` | `OpenEnded` | 개방형·폐쇄형 같은 환매 구조 |
| `axis_issuanceType` | `AdditionalType` | 추가형·단위형 같은 설정 구조 |
| `axis_listingType` | `Listed`, `Unlisted` | 상장·비상장 여부 |
| `axis_classDifferentiation` | `SingleClass` | 클래스 구분 축 |
| `axis_investorEligibility` | `PublicOffering` | 공모·사모 같은 투자자 자격 |

중요한 점은 이 6개 축이 실제 `datarows`의 45개 컬럼에는 없다는 것이다. 스키마 워크북이 보여주는 **정규화 목표 또는 분류 예시**에 가깝다.

- 실제 마스터를 조회할 때 `axis_*` 컬럼이 있다고 가정하면 안 된다.
- 8개 예시 행만으로 전체 95,619행의 분포를 추정하면 안 된다.
- 향후 정규화 파이프라인이 이 축을 생성한다면 원본 필드와 매핑 규칙을 별도로 관리해야 한다.

예를 들어 상장 여부는 상품명과 별도 상장상품 마스터를 활용할 수 있지만, 이 원본 테이블 자체에는 명시적인 상장 여부 필드가 없다.

## 6. 필드 간 핵심 관계

### 6.1 원본 행과 종목 성과

```text
원본 행 95,619
    ↓ itm_no로 중복 제거
종목·클래스 11,139
    ↓ 유효 rptt_ksd_itm_no로 묶기
대표펀드군 2,626
```

성과 순위를 만들 때는 `itm_no` 단위가 기본이다. 같은 대표펀드군의 여러 클래스가 상위권을 모두 차지하는 것을 막고 싶다면 대표펀드군별 대표 클래스를 하나 선정한다.

대표 클래스 선정 규칙은 데이터에 없으므로 다음 중 하나를 별도로 결정해야 한다.

- 현재 판매중인 클래스 우선
- 당사 판매 클래스 우선
- 개인 가입 가능 클래스 우선
- 순자산이 있는 클래스 우선
- 수수료가 낮은 클래스 우선: 현재 테이블에는 수수료 필드가 없어 외부 데이터 필요

### 6.2 순자산 합계

금지되는 계산:

```text
전체 펀드 순자산 = 원본 95,619행의 fd_nast_suma 합계
```

같은 `itm_no`의 순자산이 속성행마다 반복되므로 원본 합계는 중복 집계다. 먼저 `itm_no`로 한 행만 남겨야 한다.

대표펀드군 단위에서도 316개 그룹은 둘 이상의 비영 순자산값을 가진다. 이 값이 클래스별 순자산인지, 같은 펀드의 중복·시점 차이인지 확인하기 전에는 그룹 안의 값을 더하지 않는다.

### 6.5 벤치마크와 운용유형

벤치마크 문자열에는 다음이 섞여 있다.

- 단일 주가지수
- 단일 채권지수
- 주식지수와 채권지수의 혼합 비중
- 현금성 지표 `CALL`
- 자체 또는 제공기관 지수

벤치마크를 구조화하려면 원문을 보존하면서 지수명과 비중을 별도 배열로 파싱해야 한다. 혼합 벤치마크를 하나의 지수명으로 취급하면 자산배분 정보를 잃는다.

### 6.6 위험등급과 수익률은 다른 축이다

위험등급은 상품 설명·규정상의 등급이고, 기간수익률은 과거 성과다. 최근 수익률이 낮다고 저위험 상품이 되거나, 수익률이 높다고 고위험 등급이 자동으로 올라가는 관계가 아니다.

추천에서는 다음을 별도로 보여준다.

- 위험등급과 기준기관
- 투자자산·지역
- 과거 기간수익률과 기준일
- 환헤지 여부
- 판매 가능 여부

## 7. 데이터 품질과 이상값

### 7.1 명백한 이상행

전체에서 한 행은 다음과 같은 비정상 조합을 가진다.

- `itm_no`가 정상 종목번호가 아닌 따옴표 문자
- `exchdg_yn`에 기관코드 형태 값
- `zrin_fd_ivst_risk_gcd`에 수탁회사코드 형태 값
- `zrin_fd_ivst_risk_grd_nm`에 `06`
- `thco_sale_yn`에 예탁원 종목번호 형태 값

열 값이 옆으로 밀렸거나 원천 행이 손상된 것으로 보인다. 이 행은 자동 격리하고 원본 제공처에 확인해야 한다.

### 7.2 센티널과 미정규화 값

| 필드 | 값 | 건수 | 처리 권장 |
| --- | --- | ---: | --- |
| `zrin_fd_ivst_risk_gcd` | 문자열 `NULL` | 18,416 | 실제 `NULL`로 변환 |
| `rptt_ksd_itm_no` | `KR0000000000` | 1,525 | 대표그룹 결측 센티널 |
| `rptt_ksd_itm_no` | `000000000000` | 976 | 대표그룹 결측 센티널 |
| `fss_itm_no` | `000000000000` | 23,409 | 감독원번호 결측 센티널 |
| `kofia_fd_ccd` | 20자리 0 | 22,131 | 분류코드 결측 센티널 |

센티널은 물리적 `NULL`과 구분해 `missing_reason`을 남긴다.

### 7.3 66행 결측 묶음

여러 필드가 정확히 66행씩 함께 결측한다.

- 대표예탁원·표준종목 관련 필드
- 설립국가, 투자지역, 운용속성
- 공모·사모 구분
- 운용사·수탁회사 코드

같은 원천 연결에 실패한 행 묶음일 가능성이 있다. 개별 필드를 각각 임의 보정하기보다 행 단위 원천 연결 실패로 관리하는 편이 안전하다.

### 7.4 수익률 이상치

18개월·2년·3년·5년 수익률에서 각각 -100% 미만 값이 5행씩 나타난다. 같은 `itm_no`의 속성 반복 때문에 하나의 잘못된 종목값이 여러 행에 복제됐을 가능성이 높다.

수익률 검증 순서:

1. `itm_no`로 중복 제거한다.
2. 누적수익률이 -100% 미만인지 검사한다.
3. 수익률 기간보다 펀드 운용기간이 충분한지 확인한다. 현재 테이블에는 설정일이 없어 외부 데이터가 필요하다.
4. 분배금 재투자와 보수 차감 정의를 확인한다.
5. 기준일과 원천 시계열로 재계산한다.

## 8. 금융상품 Agent가 안전하게 사용하는 규칙

### 8.1 질문마다 분석 단위를 먼저 선택한다

| 사용자 질문 | 권장 단위 |
| --- | --- |
| 특정 판매클래스의 성과·위험 | `itm_no` |
| 같은 펀드의 클래스 비교 | `rptt_ksd_itm_no` 안의 고유 `itm_no` |
| 펀드 유형·지역 분포 | 고유 `itm_no` 또는 대표펀드군 |
| 원본 속성코드 보유 여부 | 복합키 원본 행 |
| 전체 펀드 수 | 목적에 따라 `itm_no` 수와 대표펀드군 수를 함께 표시 |

“펀드가 몇 개냐”는 질문에 95,619라고만 답하면 안 된다. 다음처럼 단위를 함께 답해야 한다.

```text
원본 속성행 95,619개
고유 펀드 종목·클래스 11,139개
유효 대표펀드군 2,626개
```

### 8.2 공모와 판매상태를 분리한다

공모펀드 검색의 기본 조건:

```text
prvo_pbff_desc = '공모'
sale_yn = '판매중'
```

당사에서 실제 가입 가능한 상품을 찾는다면 `thco_sale_yn = 'Y'`를 추가하되, 판매채널의 최신 상품상태를 별도로 확인한다.

### 8.3 성과 비교 규칙

- `itm_no`로 먼저 중복 제거한다.
- 비교 기간이 같은 수익률 필드만 사용한다.
- 수익률 결측 종목은 0으로 채우지 않는다.
- -100% 미만 이상치를 제외하고 사유를 남긴다.
- 수익률 기준일을 확보하지 못하면 “파일 내 제공 수익률”이라고 제한을 표시한다.
- 장기수익률이 있는 상품만 고르면 오래된 펀드에 유리한 생존편향이 생길 수 있음을 알린다.
- 대표펀드군 안의 여러 클래스가 중복 노출되지 않도록 대표 클래스 선정 규칙을 적용한다.

### 8.4 Agent가 답할 수 없는 질문

이 테이블만으로는 다음을 정확히 답할 수 없다.

- 총보수·판매수수료가 가장 낮은 펀드
- 환매수수료와 환매 가능일
- 최소가입금액
- 실제 설정일과 운용기간
- 최신 기준가와 기준일
- 수익률 산식·기준일·분배금 재투자 여부
- 클래스 A, C, E, S 등의 정확한 비용·채널 차이
- 현재 운용사·수탁사 이름: 코드만 있고 명칭 매핑이 없음

이 질문에는 추가 펀드 기준가 시계열, 수수료, 클래스, 기관 마스터가 필요하다.

### 8.5 결정론적 처리와 LLM 역할

```text
코드·SQL 담당
├─ 중복 제거
├─ 공모·판매중 필터
├─ 결측·센티널 정규화
├─ 수익률 이상치 검사
├─ 순위·합계 계산
└─ 대표클래스 선정

LLM 담당
├─ 사용자 질문을 필터 조건으로 변환
├─ 펀드 유형과 위험을 쉬운 말로 설명
├─ 벤치마크·상품명의 의미검색
└─ 데이터 제한과 근거를 자연어로 전달
```

LLM이 원본 95,619행을 직접 보고 중복을 추측하게 하지 않는다. 중복 제거와 금융계산은 항상 결정론적으로 수행한다.

## 11. 구현 체크리스트

### 적재

- [ ] 원본 워크북은 변경하지 않고 비추적 상태로 유지한다.
- [ ] 제공 복합키의 유일성을 검사한다.
- [ ] 문자열 `NULL`과 센티널 식별자를 정규화한다.
- [ ] 명백한 열 밀림 이상행을 격리한다.
- [ ] 원본값과 정규화값을 모두 보존한다.

### 중복과 집계

- [ ] 성과·위험·순자산 비교 전 `itm_no`로 중복 제거한다.
- [ ] 대표펀드군 센티널을 그룹키로 사용하지 않는다.
- [ ] 대표펀드군 안의 순자산을 정의 없이 합산하지 않는다.
- [ ] 사용자에게 행·종목·대표펀드군 중 어떤 개수를 보여주는지 표시한다.

### 검색과 추천

- [ ] 공모 필터와 판매중 필터를 별도로 적용한다.
- [ ] 해외투자·역외·외화기준가·환헤지를 구분한다.
- [ ] 위험등급명은 코드에서 표준화한다.
- [ ] 수익률 결측을 0으로 바꾸지 않는다.
- [ ] 수익률 기준일 부재를 결과에 표시한다.
- [ ] 비용·클래스 차이는 외부 데이터 없이는 단정하지 않는다.

## 12. 분석 범위와 재현 기준

- 스키마 워크북의 45개 필드명, 타입, 한글명을 확인했다.
- 데이터 워크북의 헤더와 실제 첫 10개 데이터 행을 확인했다.
- 전체 95,619행에 대해 필드별 결측, 0, 주요 분류, 식별자 반복을 집계했다.
- 제공 복합키의 유일성과 `itm_no` 반복 구조를 검증했다.
- 대표펀드번호의 센티널을 제외하고 대표펀드군 구조를 분석했다.
- 동일 `itm_no` 안에서 순자산·위험등급·모든 기간수익률이 반복되는지 교차 검증했다.
- 통화와 외화기준가 여부, 공모·사모 설명, 판매상태와 당사판매 여부를 교차 검증했다.
- 원본의 행 단위 종목번호, 펀드명, 기관코드는 이 문서에 복제하지 않았다.
- 이 문서는 특정 펀드의 추천서가 아니라 데이터 이해와 구현을 위한 레퍼런스다.
