# 국내 ETF 마스터 데이터 분석 및 필드 레퍼런스

**테이블 ID:** `PREF01N001`

> 이 문서는 로컬에 보관된 주최 측 원본 워크북을 분석해 작성한 파생 문서다. 원본 워크북과 행 단위 원본값은 저장소에 포함하지 않는다. 필드명과 실제 값만으로 확정할 수 없는 의미는 `추정` 또는 `확인 필요`로 표시한다.

## 1. 한눈에 보는 결론

- 한 행은 국내 거래소에 등록된 **ETF 또는 ETN 개별 종목 하나**다.
- 테이블 이름은 국내 ETF 마스터지만 실제로는 ETF 1,202개와 ETN 532개가 함께 들어 있다. ETF만 찾을 때는 반드시 `pd_grp_no = 'ETF'`를 적용해야 한다.
- `pd_itm_no`와 `pd_itm_no_ma`는 각각 1,734개 행에서 모두 고유하고 결측이 없다. 제공 스키마는 거래소코드까지 포함한 복합키를 표시하지만 실제 데이터에서는 두 상품번호가 각각 단독 식별자로도 동작한다.
- 국내 ETF는 국내 자산 ETF를 뜻하지 않는다. 국내 거래소에 상장됐다는 뜻이며, 투자지역은 국내·미국·중국·글로벌 등으로 다양하다.
- 시장가격과 NAV, 가격수익률, AUM, 거래량, 위험등급, 연금거래 여부를 한 테이블에서 조회할 수 있다.
- 데이터 워크북에는 엑셀 수식이 없으며 계산이 끝난 값이 저장된 스냅샷이다.
- 반면 기초지수, 총보수, 배당, 괴리율, 추적오차, 장중 iNAV, 실시간 가격은 결측 또는 0이 많아 그대로 사용하기 어렵다.
- 파일 추출 표시는 2026-07-11이지만 일간·주간 데이터는 대부분 2026-06-15 기준이다. 추출일과 지표 기준일을 분리해야 한다.
- `pd_tr_yn`은 거래가능 여부가 아니라 스키마상 **거래정지 여부**다. 값 `0`이 정상 거래, `1`이 거래정지로 해석되므로 이름만 보고 반대로 필터링하면 안 된다.
- ETF와 ETN은 법적 구조와 위험이 다르다. ETN에는 발행 증권사의 신용위험이 있으므로 ETF와 동일 상품군으로 설명하거나 추천하면 안 된다.

### 2.1 행의 단위와 키

한 행은 하나의 상장 상품이다.

```text
국내 거래소 상장지수상품
├─ ETF 종목 A → pd_itm_no A
├─ ETF 종목 B → pd_itm_no B
└─ ETN 종목 C → pd_itm_no C
```

제공 스키마에는 다음 세 필드가 PK로 표시되어 있다.

- `pd_exg_mkt_cd`
- `pd_itm_no`
- `pd_itm_no_ma`

실제 데이터에서는 `pd_itm_no`와 `pd_itm_no_ma`가 각각 단독으로도 전 행에서 고유하다. 반면 `pd_exg_mkt_cd`는 거의 모든 행이 같은 값이고 1개 결측도 있으므로 단독키가 아니다.

원본 적재 시 제공된 복합키를 유지하되, 조회용 대표키는 `pd_itm_no`를 사용하는 방식이 가장 자연스럽다.

AUM과 유동성은 다른 개념이다.

- AUM이 크다: 상품 전체 규모가 크다.
- 거래대금·거래량이 크다: 시장에서 실제 매매가 활발하다.

큰 ETF도 거래가 적을 수 있고, 작은 상품도 단기 거래가 활발할 수 있다. 유동성 비교에는 거래량보다 가격 단위 차이를 보완하는 거래대금이 더 적합할 수 있다.

## 5. ETF와 ETN을 먼저 분리해야 하는 이유

| 구분 | ETF | ETN |
| --- | --- | --- |
| 데이터 필터 | `pd_grp_no = 'ETF'` | `pd_grp_no = 'ETN'` |
| 법적 구조 | 집합투자기구의 지분 | 증권사가 발행한 채무증권 |
| 상품 제공기관 | 자산운용사 | 발행 증권사 |
| 핵심 위험 | 기초자산 가격, 추적오차, 유동성, 비용 | 기초지수 가격, 발행사 신용, 유동성, 만기·조기상환 조건 |
| AUM 의미 | 운용자산규모로 사용 가능 | 0 또는 구조적으로 부적합할 수 있음 |
| 비용 필드 | 총보수와 기타비용 | ETF 보수와 동일 의미라고 단정 불가 |
| NAV 표현 | 순자산가치 | 지표가치 또는 상환가치에 가까울 수 있음 |

ETN을 ETF 검색 결과에 포함하면 다음 문제가 생긴다.

- 펀드 운용사와 채무증권 발행사를 같은 개념으로 설명하게 된다.
- ETN의 발행사 신용위험이 누락된다.
- AUM과 보수처럼 ETF 중심 필드를 ETN에 잘못 적용한다.
- 만기와 조기상환 구조가 설명에서 빠질 수 있다.

국내 ETF라는 사용자 표현은 기본적으로 ETF만 의미하도록 처리하고, ETN은 사용자가 명시적으로 포함한 경우에만 함께 검색한다.

## 6. 필드 간 핵심 관계

### 6.1 시장가격과 NAV

- 시장가격: `du_clpr`
- 주당 NAV: `du_last_nav` 또는 `pd_nav_pshr`
- 제공 괴리율: `du_diff_rt`

동일 기준일과 단위가 확인되면 괴리율은 다음처럼 재계산할 수 있다.

```text
괴리율(%) = (시장 종가 ÷ NAV - 1) × 100
```

현재 `du_diff_rt`는 채워진 1,517개가 모두 0이므로 제공값 대신 결정론적 재계산을 검토해야 한다. 재계산 결과에는 사용한 시장가격, NAV, 기준일을 증거로 남긴다.

### 6.2 NAV와 AUM

ETF에서 일반적인 관계는 다음과 같다.

```text
AUM ≈ 주당 NAV × 유통 또는 발행 주식수
```

실제 표본에서도 `du_last_aum`과 `du_last_nav × pd_circ_stk_cnt`가 일치하는 사례가 확인됐다. 그러나 세 종류의 주식수가 서로 다른 종목도 있으므로 어떤 주식수를 적용할지 필드별 정의가 필요하다.

### 6.3 기준가와 유통순자산총액

표본 ETF에서 다음 관계가 확인됐다.

```text
pd_circ_net_tamt = du_bpr × pd_circ_stk_cnt
```

따라서 `pd_circ_net_tamt`는 최신 NAV 기반 AUM이라기보다 기준가와 유통주식수의 결합값일 수 있다. `du_last_aum`과 같은 값으로 취급하지 않는다.

### 6.4 가격수익률과 분배금

`du_er_*`는 가격 또는 총수익 중 어느 기준인지 공식 정의가 필요하다. 실제 분배금 필드가 모두 0이므로 분배금을 포함한 총수익률인지 데이터만으로 검증할 수 없다.

기간수익률을 비교할 때는 다음 조건을 맞춘다.

- 동일 기간
- 동일 수익률 정의
- 레버리지·인버스 여부
- ETF와 ETN 구분
- 상장기간이 비교 기간보다 충분한지
- `-100` 센티널 여부

### 6.5 레버리지와 장기수익률

`cu_lev_fector = 2`가 장기간 기초지수 누적수익률의 정확히 2배를 뜻하는 것은 아니다. 레버리지 상품은 보통 일간 수익률 배수를 목표로 하므로 변동성과 경로에 따라 장기 결과가 달라진다.

따라서 장기수익률 순위를 만들 때 표준형, 레버리지형, 인버스형을 기본적으로 분리한다.

### 6.6 규모와 유동성

| 질문 | 우선 필드 |
| --- | --- |
| 상품 규모가 큰가 | `du_last_aum`, `pd_net_tamt` |
| 오늘 거래가 활발한가 | `du_val_1d`, `du_vol_1d` |
| 평소 거래가 활발한가 | `du_val_1m`, `du_vol_avg_1m` |
| 최근 유동성이 변했는가 | 1일·5일·1개월 거래대금 비교 |

서로 다른 가격대 상품의 유동성을 비교할 때는 거래량만 보는 것보다 거래대금을 함께 보는 것이 안전하다.

### 7.4 상태별 처리 원칙

| 원본 상태 | 가능한 의미 | 처리 원칙 |
| --- | --- | --- |

| 숫자 0 | 실제 0 또는 미산출 기본값 | 필드별 유효성 규칙 없이 확정 금지 |
| 수익률 `-100` | 전액 손실 또는 미산출 센티널 | 상장일·가격과 검증 후 분류 |
| 날짜 `99991231` | 종료일 없음 또는 센티널 | 일반 날짜와 분리 |
| 통화 `CURR_CD_000` | 해당없음 또는 비정상 코드 | 통화 집계에서 격리 |
| 매우 큰 장기수익률 | 레버리지 효과 또는 이상값 | 레버리지·기간과 함께 검증 |
| `cu_strtegy = 'C'` | 미정 코드 | 전략명으로 임의 번역 금지 |

## 8. 분류 축

### 8.1 실제 마스터에서 직접 사용하는 분류

가장 안정적인 분류는 다음 세 필드다.

```text
pd_grp_no          ETF / ETN
wu_inv_ast_type    주식 / 채권 / 원자재 / 혼합자산 / 단기자금 / 통화 / 부동산 / 기타
wu_inv_rgn         국내 / 미국 / 글로벌 / 중국 / 아시아 / 일본 / 인도 ...
```

### 8.2 스키마 샘플이 제안하는 정규화 축

스키마 워크북의 100개 샘플에는 실제 데이터 필드와 별도로 다음 영문 분류 축이 있다.

| 축 | 값 |
| --- | --- |
| `axis_assetType` | Equity, Bond, MoneyMarket, MixedAsset, Commodity, Currency, RealEstate |
| `axis_region` | Domestic, Overseas |
| `axis_strategy` | Passive, Active |
| `axis_replicationMethod` | Physical, Synthetic |
| `axis_leverageType` | Standard, Leveraged2X, Inverse1X, Inverse2X |
| `axis_underlyingScope` | SectorTheme, MarketRepresentative, SingleStock |
| `axis_distributionType` | Distributing, TotalReturn |

이 축은 검색용 공통 분류를 설계하는 참고자료이지, 실제 1,734개 행에 이미 저장된 필드는 아니다.

주의할 점은 다음과 같다.

- 실제 `cu_lev_fector`에는 ±3배, 1.5배, -0.5배도 있지만 샘플 축은 네 가지 유형만 제시한다.
- `axis_distributionType`을 만들 실제 분배금 필드는 현재 사용할 수 없다.
- `axis_underlyingScope`의 변환 규칙은 제공되지 않았다.
- ETN이 샘플 분류 축에 어떻게 포함되는지 별도 확인이 필요하다.

## 9. 금융상품 Agent에서의 안전한 사용 규칙

### 9.1 ETF 검색의 기본 필터

```text
ETF 후보
├─ pd_grp_no = 'ETF'
├─ pd_sale_yn = '1'
├─ pd_tr_yn = '0'
├─ pd_lstg_dt <= 기준일
├─ pd_lste_dt > 기준일 또는 pd_lste_dt = '99991231'
├─ 필요한 지표가 NULL·센티널이 아님
└─ 지표 기준일을 답변에 표시
```

이 조건은 데이터상 후보를 만드는 규칙이다. 실제 주문 가능 여부나 계좌별 거래 제한까지 증명하지는 않는다.

### 9.2 자산군과 지역 검색

- 자산군은 `wu_inv_ast_type`을 우선 사용한다.
- 투자지역은 `wu_inv_rgn`을 우선 사용한다.
- `국내 ETF`에서 국내는 상장시장을 뜻하므로 투자지역 국내 조건을 자동 추가하지 않는다.
- 해외 자산 ETF라도 `pd_curr_cd`는 KRW일 수 있다. 거래통화와 기초자산 통화노출을 분리한다.
- 환헤지 여부는 별도 구조화 필드가 없으므로 상품명만 보고 확정하지 않는다.

### 9.3 수익률 비교

- 동일 기간끼리 비교한다.
- 표준형, 레버리지형, 인버스형을 기본적으로 분리한다.
- ETF와 ETN을 기본적으로 분리한다.
- `-100`을 유효 수익률로 사용하기 전에 상장기간과 가격을 검사한다.
- 수익률이 가격수익률인지 총수익률인지 정의가 확인되지 않았음을 표시한다.
- 서로 다른 기준일의 값을 한 순위표에 섞지 않는다.

### 9.4 비용 비교

`cu_charge_rt`가 있는 상품만 비용 비교 후보로 사용하고, 값이 없는 상품을 보수 0으로 취급하지 않는다. 현재 충족률이 약 12.51%이므로 “전체 국내 ETF 중 가장 저렴하다”는 결론을 만들 수 없다.

### 9.5 괴리율과 추적오차

- `du_diff_rt`와 `du_chas_errt`는 현재 모두 0이므로 원본 지표로 사용하지 않는다.
- 괴리율은 동일 기준일의 종가와 NAV로 결정론적으로 재계산할 수 있다.
- 추적오차는 기초지수 시계열이 없으므로 이 파일만으로 재계산할 수 없다.
- `nru_mkt_inav`가 없으므로 장중 괴리율을 계산할 수 없다.

### 9.6 유동성 비교

- 단기 상태는 `du_val_1d`, 평소 상태는 `du_val_1m`을 함께 본다.
- 거래대금이 0이거나 결측인 상품을 유동성이 좋다고 설명하지 않는다.
- AUM이 크다는 이유만으로 유동성이 좋다고 단정하지 않는다.
- 거래정지 상품은 유동성 순위에서 제외한다.

### 9.7 연금거래 후보

1. `pd_pen_tr_yn = 'Y'`를 먼저 적용한다.
2. 그다음 `pd_pen_risk_nm`의 안전자산·위험자산 구분을 표시한다.
3. `pd_risk_nm`의 상품위험등급도 별도로 보여 준다.
4. 연금계좌 편입한도나 개인별 적합성은 이 테이블로 판단하지 않는다.

### 9.8 증거 패킷

ETF·ETN 검색과 비교 답변에는 최소한 다음을 남긴다.

- 소스 테이블과 파일 추출일
- 사용한 일간·주간 갱신일
- `pd_itm_no`, 상품명, ETF·ETN 구분
- 투자자산군과 투자지역
- 레버리지 배수와 운용전략
- 판매 여부, 거래정지 여부, 거래개시·종료일
- 사용한 가격·NAV·수익률·AUM·유동성 필드와 단위
- 결측, 0, `-100`, `99991231` 처리
- 계산식과 제외 이유
