# 공식 평가 API 규격

**Source:** 대회 주최측 API 호출 안내 및 참여자 공유용 과제설명 자료

**Recorded:** 2026-08-12

**Status:** Official evaluation contract supplied by the user

이 문서는 주최측이 전달한 평가 API 규격을 구현 기준으로 정리한다. 주최측이 명시한 요구사항과 프로젝트 내부 해석을 구분하며, 서버 구현 자체는 별도 승인된 배포 계획에서 진행한다.

직접 전달된 API 호출 안내를 하드 계약으로 우선한다. 참여자 공유용 과제설명 자료의 `문항당 60초 이내`는 권장 응답시간으로 추가 적용하며, 직접 안내의 300초 타임아웃을 대체하지 않는다.

## 1. 제출과 접근 조건

- 참가팀은 네이버클라우드 또는 개인 서버 자원에 Agent를 API 형태로 구성한다.
- 서버 종류는 자유지만 Public 망에서 접근할 수 있어야 한다.
- 실제 API End-point 주소를 `README.md`에 반드시 명시한다.
- 도메인이나 서브도메인은 필수가 아니며 공인 IP를 직접 제출할 수 있다.
- HTTP가 기본이며 HTTP는 80번 포트를 사용한다.
- HTTPS도 허용하며 HTTPS는 443번 포트를 사용한다. 자체 서명 인증서도 허용된다.
- 별도 인증 헤더는 사용하지 않는다. 접근 제어가 필요하면 추후 공지되는 주최측 발신 IP 대역을 허용하는 방식을 사용한다.
- 개인용 장비를 사용할 때는 외부 접근 가능한 정적 URL을 제출할 수 있고, `ngrok` 같은 터널링 서비스도 사용할 수 있다.

## 2. 요청 규격

주최측은 다음 GET 요청으로 비공개 평가질의를 전달한다.

```http
GET {team-end-point}/answer?question_id={질의 ID}&question={평가 질의}
```

### 고정 조건

| 항목 | 규격 |
| --- | --- |
| HTTP method | `GET` |
| Path | `/answer` 고정 |
| Query parameter | `question_id`, `question` |
| 인증 헤더 | 사용하지 않음 |
| 요청 순서 | 팀별로 한 번에 1건씩 순차 전송 |
| 문항별 타임아웃 | 300초 |
| 권장 응답시간 | 60초 이내 |
| 재시도 | 타임아웃 또는 5xx 응답 시 최대 2회 |

`question`은 URL query parameter이므로 UTF-8 문장을 URL encoding한 상태로 전달받을 수 있어야 한다.

`question_id`와 `question` 이외의 정의되지 않은 query parameter가 포함돼도 이를 무시하거나 안전하게 처리하며 500 오류를 반환하지 않는다.

### 요청 예시

```text
GET /answer?question_id=Q-001&question=평가%20질의
```

## 3. 응답 규격

응답은 `Content-Type: application/json; charset=utf-8`로 반환하며, 다음 다섯 필드를 모두 포함한다.

```json
{
  "question_id": "Q-001",
  "question": "평가 질의 원문",
  "retrieved_context": "답변 생성에 참고한 검색 문서",
  "think_trace": "사고, 추론, 도구 사용 과정",
  "answer": "최종 생성 답변"
}
```

### 필드 정의

| 필드 | 타입 | 의미 | 프로젝트 출력 원칙 |
| --- | --- | --- | --- |
| `question_id` | string | 요청으로 받은 질의 ID | 요청값을 그대로 연결한다. |
| `question` | string | 평가 질의 원문 | 요청 원문을 보존한다. |
| `retrieved_context` | string | 답변에 사용한 검색 문서 | 여러 문서는 문자열 안에서 구분 태그를 사용해 연결하고, 출처와 기준일을 식별할 수 있게 한다. |
| `think_trace` | string | 사고·추론·도구 사용 과정 | 원시 내부 사고과정 대신 의도, 하위 작업, 사용 도구, 필터, 계산, 출처, 제외·제한을 담은 간결한 실행기록을 반환한다. |
| `answer` | string | 최종 생성 답변 | 검증과 Claim Gate를 통과한 최종 답변만 반환한다. |

모든 필드 값은 반드시 문자열이다. `retrieved_context`에 여러 문서를 넣는 구분 방식은 자유이며 평가 대상이 아니다.

각 필드의 명시적인 길이 제한은 없다. 다만 평가 시스템이 한 번에 처리할 수 없을 정도로 길면 초과분이 평가에 반영되지 않을 수 있으므로, 근거와 실행기록은 필요한 내용만 압축해서 반환한다.

제공·승인 데이터로 확인할 수 없는 질문도 예외 응답이나 5xx로 처리하지 않는다. `200 OK`와 동일한 다섯 문자열 필드를 반환하고, `answer`에 확인할 수 없음과 그 근거를 명시한다.

## 4. 호출과 장애 처리

### 4.1 주최측 명시사항

- 평가 요청은 동시에 들어오지 않고 한 건씩 순차적으로 들어온다.
- 주최측은 한 문항의 응답을 최대 300초 기다린다.
- 타임아웃 또는 5xx 오류가 발생하면 최대 2회 재시도한다.

### 4.2 프로젝트 구현 원칙

- 외부 요청은 순차적이지만, 한 요청 내부에서 독립적인 Product Specialist나 데이터 조회를 병렬로 실행하는 설계는 가능하다.
- 같은 `question_id`와 `question`이 반복되어도 부작용 없이 같은 데이터 버전을 기준으로 처리하는 멱등성을 보장한다.
- 프로젝트의 내부 제한시간은 300초를 전부 사용하지 않는다. 응답 직렬화와 네트워크 전달 시간을 남기고 안전하게 종료해야 한다.
- 정상 지원 질문은 60초 이내 완료를 상한 권장치로 보고, 프로젝트의 더 짧은 내부 성능 목표를 우선한다.
- 평가 규격은 중간 진행 이벤트나 스트리밍 응답을 정의하지 않는다. 검증을 마친 완전한 JSON 객체를 한 번에 반환하는 것을 기준으로 한다.

## 5. 평가 운영 조건

- 서버 운영은 `09.07 ~ 09.20` 사이에 주제별로 별도 공지되는 기간에 수행한다.
- 각 주제의 평가 기간은 최대 1주를 넘기지 않을 예정이며 정확한 날짜는 추후 공지된다.
- 주최측 발신 IP 대역은 추후 공지된다.
- 제출 마감 후 결과물을 변경해서는 안 된다.
- 제출 결과 변경이 아닌 서버 장애 등 불가피한 사유의 서버 재기동은 실격 사유가 아니다.

정확한 평가일, 발신 IP, 제출 마감과 변경 동결 시각은 후속 공지를 받아 별도 운영 체크리스트에 반영해야 한다.

## 6. 프로젝트 해석: 문맥 처리에 미치는 영향

공식 요청에는 `question_id`와 `question`만 있고 세션 ID, 이전 대화, 대화 이력 필드는 없다. 이 계약에서 안정적으로 평가받기 위해 평가용 Agent는 다음 원칙을 따른다.

- 각 요청을 독립적인 단일 질문으로 처리한다.
- 이전 평가 요청의 질의나 답변에 의존하지 않는다.
- `question_id`는 요청·응답 연결과 로그 추적에 사용하며 대화 세션 키로 사용하지 않는다.
- 하나의 `question` 문자열 안에 여러 문장이 있으면 그 문장들은 하나의 `RequestContext`에서 함께 분석한다.
- `이 상품`, `그 운용사`, `위 상품들` 같은 표현은 같은 `question` 안의 앞 문장이나 앞 단계 결과에만 바인딩한다.
- 사용자에게 후속 질문을 보낼 별도 상호작용 규격이 없으므로 승인된 기본값, 복수 후보, 명시적 제한 또는 거절 중 하나로 한 번에 답한다.

## 7. 구현 수용 기준

- `GET /answer`가 `question_id`와 UTF-8 `question`을 받는다.
- 응답의 Content-Type은 `application/json`이다.
- 정상·제한·답변 불가 응답 모두 가능하면 60초 이내에 완료한다.
- 응답에는 정확히 요구된 다섯 필드가 존재하고 모든 값이 문자열이다.
- `question_id`와 `question`은 요청과 응답에서 대응된다.
- 후속 질문이나 이전 요청 상태 없이 한 번의 응답으로 끝난다.
- `retrieved_context`는 답변에 실제로 사용한 근거만 포함한다.
- `think_trace`는 간결한 실행기록이며 원시 내부 사고과정을 노출하지 않는다.
- 재시도된 동일 요청은 외부 상태를 변경하지 않는다.
- 정의되지 않은 query parameter가 추가돼도 500 오류를 반환하지 않는다.
- 답변 불가 질문도 `200 OK`와 동일한 응답 스키마를 사용한다.
- 300초 이전에 완전한 JSON 응답을 종료한다.
- End-point 주소가 제출용 `README.md`에 명시된다.
- 서버가 지정된 평가 기간 동안 Public 망에서 접근 가능하다.

## 8. 주최측 제공 호출 예시

```python
import requests

url = "http://<public-ip>/answer"
params = {
    "question_id": "Q-001",
    "question": "평가 질의",
}

response = requests.get(url, params=params, timeout=300)
result = response.json()
```

```bash
curl -G "http://<public-ip>/answer" \
  --data-urlencode "question_id=Q-001" \
  --data-urlencode "question=평가 질의"
```

예시 IP는 참고용이며 실제 제출 End-point가 아니다.
