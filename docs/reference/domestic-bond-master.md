## 1. 한눈에 보는 결론

- 한 행은 발행사 하나가 아니라 **발행 조건과 만기가 특정된 개별 채권 종목 하나**다.
- `PD_NO`는 42,394개 행에서 결측과 중복이 없어 실무상 종목 기본키로 사용할 수 있다. 다만 제공된 스키마에는 PK로 표시되어 있지 않다.
- 데이터는 상품명과 발행조건 같은 정적 마스터 정보뿐 아니라 매수수익률, 평가가격, 듀레이션처럼 시점에 따라 달라지는 스냅샷 정보도 함께 담고 있다.
- 파일에 종목이 존재한다는 사실만으로 현재 판매 가능하거나 매수 가능하다고 판단할 수 없다.
- `NULL`, 숫자 `0`, 날짜 `0`, 날짜 `99991231`, 통화코드 `000`이 서로 다른 의미로 섞여 있으므로 정규화 전에 모두 원본 그대로 보존해야 한다.
- 매수 및 세후수익률 계열은 881개 행, 전체의 약 2.08%에만 존재한다. 그중 `BUYABLE_QUANTITY`가 양수인 행은 325개뿐이다.
- 신용등급, 평가가격, 듀레이션 계열도 상당한 결측이 있다. 결측값을 유사 종목으로부터 추정하면 안 된다.

### 2.1 행의 단위

같은 발행사가 같은 종류의 채권을 발행하더라도 발행일, 만기일, 표면금리 또는 회차가 다르면 서로 다른 `PD_NO`를 가진 별도 행이다.

```text
발행주체
└─ 상품 종류
   ├─ 발행 회차 A → PD_NO A
   ├─ 발행 회차 B → PD_NO B
   └─ 발행 회차 C → PD_NO C
```

따라서 발행사 단위 집계와 종목 단위 검색을 구분해야 한다. 단순히 `PD_PBCM`으로 묶으면 만기와 위험이 서로 다른 종목들이 하나로 합쳐진다.

`ISU_BAL_AMT`와 `BUYABLE_QUANTITY`는 다르다.

듀레이션과 컨벡서티는 금리가 변할 때 채권가격이 얼마나 움직이는지를 설명한다.

```text
가격변화율 ≈ -듀레이션 × 금리변화
             + 1/2 × 컨벡서티 × 금리변화²
```

이 식은 개념 설명용이다. 실제 계산에서는 제공기관의 듀레이션 종류, 금리 단위, 현금흐름 가정이 확인되기 전까지 임의 계산값과 원본값을 혼합하지 않는다.

### 4.8 평가가격과 적용수익률

| 필드 | 타입 | 의미 | 관찰 및 주의점 |
| --- | --- | --- | --- |
| `EVAL_PRICE` | double precision | 현재 기준 평가가격 | 약 24.94% 결측. 가격 기준 액면과 단위 확인 필요 |
| `APPLIED_YIELD` | double precision | 평가가격 산출에 적용한 수익률로 추정 | 0, 음수, 매우 큰 이상값이 있어 범위검사 필요 |
| `DIRTY` | double precision | 경과이자를 포함한 현재 가격으로 추정 | 약 31.55% 결측. 필드명이 가격임을 명시하지 않아 정의 확인 필요 |
| `NDY_EVAL_PRICE` | double precision | 다음 영업일 평가가격으로 추정 | 0이 많으며 미산출 기본값과 실제 0 구분 필요 |
| `NDY_APPLIED_YIELD` | double precision | 다음 영업일 적용수익률로 추정 | 다음 날 기준값이지 수익률 전망치가 아님 |
| `NDY_DIRTY` | double precision | 다음 영업일 더티가격으로 추정 | 현재 더티가격과 같은 단위인지 확인 필요 |

일반적인 채권 관계는 다음과 같다.

```text
시장수익률 상승 → 채권 평가가격 하락
시장수익률 하락 → 채권 평가가격 상승

더티가격 ≈ 클린가격 + 경과이자
```

첫 10행 중 한 행에서 `DIRTY - EVAL_PRICE = 170`이 확인되어 `EVAL_PRICE`가 경과이자 제외 가격, `DIRTY`가 경과이자 포함 가격이라는 해석을 뒷받침한다. 그러나 공식 가격 정의가 없으므로 확정 규칙으로 사용하기 전 제공기관 확인이 필요하다.

## 5. 필드 간 핵심 관계

### 5.1 표면금리와 수익률

`SRFC_IRT`는 발행계약에 정해진 쿠폰금리다. `BUY_YIELD`와 `APPLIED_YIELD`는 가격과 평가시점에 따라 달라지는 수익률이다.

같은 표면금리의 채권이라도 다음 조건이 다르면 수익률은 달라질 수 있다.

- 매수가격
- 만기까지 남은 기간
- 지급받을 이자와 원금
- 세금 적용 방식
- 발행자 신용위험
- 시장금리와 유동성

### 5.2 매수수익률과 평가수익률

- `BUY_YIELD`: 판매 또는 매수 조건에 사용되는 수익률
- `APPLIED_YIELD`: 평가가격 산출에 사용된 시장 평가수익률로 추정

두 값은 목적과 기준시점이 다를 수 있으므로 서로 동일하다고 가정하면 안 된다.

### 5.3 현재값과 다음 날 값

다음 필드는 현재값과 다음 영업일 값의 짝으로 보인다.

| 현재 | 다음 날 |
| --- | --- |
| `DUR` | `NDY_DUR` |
| `COV` | `NDY_COV` |
| `EVAL_PRICE` | `NDY_EVAL_PRICE` |
| `APPLIED_YIELD` | `NDY_APPLIED_YIELD` |
| `DIRTY` | `NDY_DIRTY` |

`NDY_*`를 미래 시장 예측으로 설명하면 안 된다. 현금흐름과 경과일을 다음 기준일로 넘겨 계산한 값일 가능성이 높다.

### 5.4 원천 신용등급과 대표 신용등급

```text
PD_EVCO_CRD_GRD
여러 평가회사 원천등급
        ↓ 대표등급 선정 또는 표준화
CRD_GRD
검색·비교용 단일등급
```

대표등급 선정 방식이 제공되지 않았으므로 원천등급과 대표등급이 다를 때 에이전트가 임의로 어느 쪽이 맞다고 판단하면 안 된다.

## 6. 결측, 0, 이상값 처리

### 6.1 서로 다른 상태를 분리한다

| 원본 상태 | 가능한 의미 | 처리 원칙 |
| --- | --- | --- |
| 빈 셀 또는 `NULL` | 미제공, 미평가, 구조적으로 해당 없음 | `NULL`로 유지하고 추정 금지 |
| 숫자 `0` | 실제 0, 만기 완료, 미산출 기본값 | 필드별 규칙 없이 유효값으로 확정 금지 |
| 날짜 `0` | 미상 또는 미입력 | 날짜 변환 실패로 격리 |
| 날짜 `99991231` | 무기한·영구채·센티널 가능성 | 일반 만기일과 분리하고 의미 확인 |
| 통화 `000` | 비정상 또는 미상 코드 | 통화별 계산과 집계에서 제외 |
| 음수 수익률 | 실제 음수금리 또는 오류 | 곧바로 제거하지 말고 다른 값과 기준일 검증 |
| 비정상적으로 큰 수익률·가격 | 단위 차이, 특수구조, 오류 | 범위검사 후 별도 검토 |

## 7. 금융상품 Agent에서의 안전한 사용 규칙

### 7.1 종목 조회

1. 정확한 식별은 `PD_NO`를 사용한다.
2. 사용자 검색은 `PD_NM`, `PD_ABRV_NM`, 영문명에 적용한다.
3. 이름 검색 결과가 여러 개면 발행일과 만기일을 함께 보여 준다.
4. 발행사명만 일치하는 종목을 하나의 상품처럼 합치지 않는다.

### 7.2 현재 매수 가능 후보

`BUYABLE_QUANTITY > 0`만으로 매수 가능하다고 답하지 않는다. 최소한 다음을 함께 확인한다.

```text
후보 조건
├─ BUYABLE_QUANTITY > 0
├─ MAT_DT가 기준일보다 미래
├─ REMAINING_DAYS > 0
├─ PD_STD_INFO_UPDATE가 허용 가능한 최신성 범위
├─ 통화 및 단위가 유효
└─ 필요한 수익률 필드가 NULL이 아님
```

최신성 허용 범위와 실제 판매 가능 여부를 확정할 별도 필드가 없으므로, 결과는 “데이터상 매수 가능 물량이 확인되는 후보”로 표현한다.

### 7.3 수익률 비교

- `BUY_YIELD`, `AFTER_TAX_YIELD`, `DEPO_EQUIV_YIELD_154`, `APPLIED_YIELD`를 같은 지표처럼 한 순위표에 섞지 않는다.
- 수익률이 백분율 포인트로 저장됐는지 확인하고 계산 시 소수로 변환한다.
- 세전과 세후, 일반과 세금우대, 판매수익률과 평가수익률을 구분한다.
- 음수와 이상값을 자동 삭제하지 말고 데이터 품질 경고와 함께 검증한다.
- `AVG_ANNUAL_TAX_YIELD`는 전부 0이므로 정의가 확인되기 전까지 검색·정렬에서 제외한다.

### 7.4 가격과 금리위험 비교

- 평가가격 단위와 기준 액면이 확인되지 않은 상태에서 서로 다른 통화의 가격을 비교하지 않는다.
- 듀레이션 종류가 확인되지 않은 상태에서는 원본 듀레이션끼리만 비교하고 자체 산출값과 혼합하지 않는다.
- `NDY_*` 값은 예측이라고 표현하지 않는다.
- `EVAL_PRICE`와 `DIRTY` 중 어떤 가격을 보여 주는지 명시한다.

### 7.5 증거 패킷

채권 검색·비교 답변에는 최소한 다음 정보를 남긴다.

- 소스 테이블과 데이터 기준일
- `PD_NO`
- 종목명과 발행사
- 발행일과 만기일
- 사용한 수익률 필드와 세전·세후 기준
- 통화와 단위
- 매수가능수량과 종목정보 갱신일
- 적용한 필터와 제외 이유
- 결측, 0, 센티널, 이상값 처리 내역

## 8. 권장 정규화 모델

원본 필드를 덮어쓰지 않고 정규화 필드를 별도로 만든다.

| 정규화 필드 예시 | 원천 | 규칙 |
| --- | --- | --- |
| `bond_id` | `PD_NO` | 공백 제거 후 원본 식별자 보존 |
| `product_name_ko` | `PD_NM` | 앞뒤 공백 제거 |
| `issuer_name` | `PD_PBCM` | 앞뒤 공백 제거, 결측 유지 |
| `issue_date` | `ISU_DT` | 유효한 `YYYYMMDD`만 날짜 변환 |
| `maturity_date` | `MAT_DT` | `0`, `99991231`은 별도 상태로 분기 |
| `coupon_rate_pct` | `SRFC_IRT` | 원본 백분율 포인트 보존 |
| `coupon_rate_decimal` | `SRFC_IRT` | 계산용으로 100으로 나눔 |
| `currency_code` | `CURR_CD` | 유효 코드 검증, `000` 격리 |
| `credit_grade_raw` | `PD_EVCO_CRD_GRD` | 원천 문자열 그대로 보존 |
| `credit_grade_representative` | `CRD_GRD` | 제공된 대표등급 그대로 사용 |
| `is_matured` | `MAT_DT`, 기준일 | 유효 만기일이 기준일 이하인지 계산 |
| `has_positive_inventory` | `BUYABLE_QUANTITY` | `> 0`, 단 현재 매수가능 확정값은 아님 |
| `data_quality_flags` | 여러 필드 | 결측, 0, 센티널, 이상값 사유 배열 |

정규화와 파생 계산은 SQL이나 일반 코드처럼 결정론적으로 실행한다. 언어모델이 날짜, 세율, 필드 매핑을 매번 추론하게 만들지 않는다.

## 9. 별도 확인이 필요한 정의

다음 항목은 데이터만 보고 완전히 확정할 수 없다.

1. `PD_CTRY_CD`가 발행국, 등록국, ISIN 관할 중 어느 기준인지
2. `ISU_BAL_AMT`와 `BUYABLE_QUANTITY`의 정확한 단위
3. `BUY_YIELD`에서 매수 주체가 고객인지 금융회사인지
4. 법인, 일반, 세금우대 수익률의 적용 세율과 투자자 유형
5. `PD_RISK_GCD` 코드 0부터 6의 한글 등급 매핑
6. `DUR`가 수정듀레이션인지 맥컬리듀레이션인지
7. `COV`의 단위와 산식
8. `EVAL_PRICE`의 기준 액면과 클린가격 여부
9. `DIRTY`가 더티가격이라는 공식 정의
10. `NDY_*`의 정확한 기준시점과 생성 방식
11. `PD_STD_INFO_UPDATE`가 어느 필드군의 갱신일인지
12. `MAT_DT=99991231`이 영구채·무기한인지 단순 센티널인지

이 정의가 확인되기 전에는 사용자 답변에 단정적인 명칭을 쓰지 않고 “데이터상”, “추정”, “확인 필요”를 표시한다.

## 10. 구현 전 체크리스트

- [ ] `PD_NO`를 종목 기본키로 검증한다.
- [ ] 원본 문자열과 `TRIM`한 문자열을 모두 보존한다.
- [ ] 숫자로 저장된 날짜를 검증 후 변환한다.
- [ ] `NULL`, 0, 센티널 값을 서로 다른 상태로 관리한다.
- [ ] 만기 경과 종목을 현재 매수 가능 후보에서 제외한다.
- [ ] 매수가능수량의 단위를 확인하거나 답변에 단위 미확정을 표시한다.
- [ ] 세전·세후·예금환산·평가수익률을 서로 다른 지표로 관리한다.
- [ ] 통화가 다른 채권의 금액과 가격을 변환 없이 합산하지 않는다.
- [ ] 신용등급 결측을 임의 등급으로 보완하지 않는다.
- [ ] 평가가격과 더티가격의 정의를 답변에 표시한다.
- [ ] 이상값 범위검사와 품질 플래그를 결정론적으로 수행한다.
- [ ] 모든 결과에 기준일, 원천 필드, 필터, 제외 이유를 남긴다.
