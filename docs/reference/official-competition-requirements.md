## 1. 과제의 핵심 목표

과제는 국내채권, 국내 ETF, 해외 ETF, 공모펀드의 정형 데이터와 필요한 공식 비정형 데이터를 Agent가 탐색·연산하고, 검색한 근거를 바탕으로 답하는 금융상품 RAG·QA를 구현하는 것이다.

주최측이 명시한 핵심 구성은 다음과 같다.

1. 정형·비정형 데이터 분석과 정제
2. 상품 도메인 특화 온톨로지
3. RDB·Vector·Graph를 결합한 금융상품 Knowledge Base
4. 자연어 질의 의도 분석과 NL2SQL
5. 검색 우선순위와 탐색 순서를 정하는 Retrieval Engine
6. 검색 Evidence만 사용하는 Answer Generator
7. 데이터에 없는 내용을 생성하지 않는 환각 방지

구현 방식에는 제한이 없다. 따라서 RDB, Vector, Graph가 각각 별도 서버나 별도 데이터베이스여야 하는 것은 아니다. 다만 최종 시스템은 숫자 필터, 의미 검색, 관계 경로 탐색을 실제로 수행하고 그 결과를 통합할 수 있어야 한다.

## 3. 평가와 답변 가능성

예선 평가 배점은 다음과 같다.

| 항목 | 비중 | 주요 평가 내용 |
| --- | ---: | --- |
| 소스코드 | 20% | 구현체, 재현 가능한 환경, README, 도메인별 온톨로지 |
| 기술 제안서 | 40% | 문제 정의, 제안 방법, 아키텍처, 기대효과, 확장성 |
| 평가 API와 답변 | 40% | 비공개 질문 정확성, 근거 표시, 응답시간 |

평가 질문은 당시 안내 기준 총 30문항 예정이며 난이도 상·중·하 각 10문항으로 구성될 수 있다. 문항 수와 배점은 변경될 수 있으므로 내부 골드 세트를 30개로 제한하지 않는다.

약 5문항은 제공·승인 데이터로 답할 수 없는 의도적인 답변 불가 문제로 구성될 예정이다. 근거 없는 답을 생성하면 감점되므로 다음 중 하나로 끝내야 한다.

- `확인할 수 없음`을 명시한다.
- 필요한 데이터나 충족되지 않은 조건을 설명한다.
- 단일 응답 계약상 실제 후속 대화를 기다리지 않고, 확인에 필요한 조건만 답변 안에 적는다.

답변 불가 여부는 이름 유사도나 LLM의 일반 지식이 아니라 기준일 데이터, 승인 출처, 온톨로지 제약으로 판정한다.

## 4. 온톨로지와 지식 그래프의 구분

기술세션은 온톨로지와 지식 그래프를 다음처럼 구분한다.

```text
Ontology / TBox
개념, 클래스, 속성, 허용 관계, 공리, 제약
예: ETF는 금융상품의 하위 클래스이고 ETN과 구분된다.

Knowledge Graph / ABox
실제 상품·기업·기관과 그 관계 인스턴스
예: 특정 ETF가 특정 종목을 편입하고 특정 운용사가 운용한다.
```

온톨로지는 용어 사전이나 프롬프트 설명에 머물러서는 안 된다. 런타임에서 다음 작업을 통제해야 한다.

- 질문 분해
- 용어 표준화와 엔티티 해소
- RDB·Graph·Vector 경로 선택
- 관계 방향과 역관계 해석
- 허용 값과 카디널리티 검증
- 답변 사실과 근거 경로 검증

RDF는 실제 사실을 Triple로 표현하고 RDFS·OWL은 클래스와 의미·공리를 선언한다. SHACL 또는 동등한 검증 규칙은 위험등급 허용 범위, 필수 운용사 관계, 상품 유형 배타성 같은 데이터 무결성을 검사한다.

## 5. 필수 온톨로지 제출 구조

도메인별 Turtle 파일은 필수 제출물이다.

```text
ontology/
├─ common.ttl
├─ bond_kr.ttl
├─ etf_kr.ttl
├─ etf_gl.ttl
└─ fund_pub.ttl
```

- `common.ttl`: `fp:Product` 같은 공통 상위 개념
- `bond_kr.ttl`: 국내채권 도메인
- `etf_kr.ttl`: 국내 ETF 도메인
- `etf_gl.ttl`: 해외 ETF 도메인
- `fund_pub.ttl`: 공모펀드 도메인

파일 존재만으로 충족되지 않는다. Task 1의 역량 질문에서 필요한 클래스·관계·제약이 실제 TTL과 지식 그래프에 연결돼야 한다.

## 6. 검색 아키텍처 요구사항

하나의 검색 방식으로 모든 질문을 해결하지 않는다.

| 검색 방식 | 맡는 역할 | 예시 |
| --- | --- | --- |
| RDB·SQL | 정확한 필터, 정렬, 집계, 숫자 계산 | AUM 1,000억 이상, 보수 0.1% 이하 |
| Graph | 명시적인 다단계 관계 경로 | 모회사 → 자회사 → ETF 편입 → 운용사 |
| Vector | 서술형 의미와 연관 문서 후보 | 상품 전략, 위험요인, 동향 |
| Keyword/BM25 | 정확한 명칭·티커·문구 검색 | 정확한 상품명, 기업명, 코드 |

복합 질문은 다음 흐름으로 처리한다.

```text
질문 이해
→ 온톨로지 Grounding
→ 의미 단위 분해
→ 저장소별 계획과 라우팅
→ RDB·Graph·Vector·Keyword 검색
→ 결과 매핑과 무결성 검증
→ Evidence 구성
→ 근거 기반 답변
```

Graph와 Vector는 SQL의 필터·순위 계산을 대체하지 않는다. Vector 유사도는 구조화 조건을 만족했다는 증거가 아니며, Graph 경로는 각 edge의 원천과 적용일을 반환해야 한다.

## 7. 문서 청크와 문맥 보존

상품 문서를 단순 고정 길이로 나누면 상품명이 있는 청크와 보수·위험 내용이 있는 청크가 분리될 수 있다. 모든 문서 청크는 최소한 다음 문맥을 유지한다.

```text
document_id
product_id
document_type
page_or_section
chunk_id
parent_chunk_id
preceding_context
published_at
effective_date
source_id
```

문서 안의 `본 펀드`, `이 상품` 같은 표현은 청크만 보고 해석하지 않고 부모 상품과 문서 구조를 따라 해소한다.

## 8. 공식 예상 질문과 요구 역량

| 질문 | 주된 요구 역량 | 필요한 검색 |
| --- | --- | --- |
| 현재 판매 가능한 원화채권 중 AA- 이상 종목 | 판매현행성, 통화, 신용등급 순서 | RDB |
| 국민성장펀드의 구조·투자전략·동향 | 정확한 상품·정책 식별, 공식 문서와 시점별 자료 | Keyword + Vector + Graph |
| 캠브리콘이 편입된 중국 반도체 ETF | 기업 별칭·증권 ID, ETF 구성종목, 지역·산업 분류 | Graph + RDB |
| 최근 6개월 동안 우주항공 테마 연결 이력이 있는 ETF | 기간이 있는 테마 관계와 공식 근거 문서 | Graph + Vector + RDB |
| 에코프로 자회사를 편입한 ETF 중 AUM이 큰 상품의 위험요인 | 기업 지배관계, 구성종목, 순위, 공식 위험 문서 | Graph + RDB + Vector |

공식 답변 불가 예시는 다음과 같다.

- 존재하지 않는 `AAAA` 신용등급 채권
- 승인 데이터에서 관계를 확인할 수 없는 `Kimi` 관련 상품
- 기준일 상품 마스터에서 정확히 식별되지 않는 `KODEX AI로봇 ETF`

이 사례들은 각각 허용 어휘 검증, 근거 없는 의미 연상 차단, 정확한 상품 식별과 기준일 검증을 시험한다.

## 9. 평가 API 보완 요구사항

- `GET /answer`를 사용한다.
- 응답은 `application/json; charset=utf-8`로 반환한다.
- 권장 응답시간은 문항당 60초 이내이며, 직접 전달된 호출 규격의 하드 타임아웃은 300초다.
- 정의되지 않은 query parameter가 추가돼도 500 오류를 반환하지 않는다.
- 답변 불가 질문도 `200 OK`와 동일한 다섯 문자열 필드를 반환한다.
- `retrieved_context`에는 실제 사용한 표·문서와 기준일을 넣는다.
- `think_trace`에는 원시 내부 사고가 아니라 조건 파싱, 검색 경로, 필터, 계산, 출처, 제외와 제한을 요약한다.

## 10. Task 1과 Task 2에 미치는 영향

### Task 1

- 공식 예상 질문과 답변 불가 질문을 골드 세트에 포함한다.
- 각 복합 질문에 저장소별 하위 작업과 관계 경로를 기록한다.
- 비정형 상품 문서, 시간 이력이 있는 테마 관계, 기업 지배관계, 구성종목과 위험근거를 추가 데이터 요구사항으로 승격한다.
- 답변 가능성 자체를 평가 대상으로 둔다.

### Task 2

- 온톨로지를 런타임 의미 통제 계층으로 설계한다.
- TBox와 ABox를 분리하되 실행 시 연결한다.
- RDB·Graph·Vector·Keyword를 통합하는 Federated Retrieval을 지원한다.
- 별도 Graph DB나 Vector DB는 필수가 아니며 성능·정확도 검증 후에만 추가한다.
- 멀티 에이전트는 공식 필수요소가 아니므로 측정 가능한 이득이 있을 때만 사용한다.
